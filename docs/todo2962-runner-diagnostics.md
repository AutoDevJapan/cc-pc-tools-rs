# Windows runner の登録停止を秘密値なしで診断する

元ToDo2962 / 製品PR149。SDKと所有sccacheの起動後にworkerがexit1となるが、
公式runnerのconfigure/run出力を破棄しているため、登録処理の失敗位置は未確定。
ネットワーク・認証・暗号化などの特定原因はまだ断定しない。

## 受入条件

- 固定のconfigure/listener各段階について、起動直前の一度限りの記録と、
  起動の成否、実終了コード、固定した出力語句の観測だけをJSONへ残す。
- 出力本文、引数、環境変数、例外本文、URL、資格情報を保存・表示しない。
  観測語句は診断だけに使い、成功・再試行・権限・資源制限の判定には使わない。
- 出力は全量を蓄積せず、分割された語句を見落とさない有限の末尾だけをRAMで保持する。
  stdout/stderrは1本のパイプへ統合し、writer自体も並行安全にする。
  子孫がパイプを保持したままなら、親が終了コード0でも2秒後に失敗を返す。
- 開始記録の保存に失敗したら子を起動しない。終了記録の保存失敗も成功にしない。
  同じ段階の再実行で旧記録を上書きしない。
- 架空の秘密文字列を出す実子プロセスを使い、成功・失敗・起動失敗・
  既存記録拒否とJSONに秘密文字列が無いことを検査する。

記録追加だけで実際の登録失敗を修復済みとはしない。正常レビュー・CI・マージ・
同ソースの現用反映後、3250の回収修復と合わせ、同じ有限予約の通常経路で
実原因を確かめる。正式製品jobの新規作成、上限解除、認証ファイル閲覧は行わない。
新しいcopied receiptを読む資格は、独立した所有記録と既存guardの正規条件で別に確認する。

| 記録 | 分かることと限界 |
|---|---|
| start無し | その段階へ到達していないか、開始記録の保存が失敗した。これだけで両者を区別しない |
| startだけ | 終了の観測・保存が完了していない。期限kill等の可能性があり、成功とは扱わない |
| resultでstarted=false | OSによる子の起動が失敗した。例外本文は残さない |
| resultでstarted=true | 実終了コードを観測した。exit_or_drainはパイプ終了失敗も含む |
| observed | 固定語句の観測だけ。HTTP例外をnetwork原因と断定せず、登録・認証・成功の証明にはしない |

この検査は架空の出力だけを使い、公式runnerの実登録や製品の正式検査成功は主張しない。

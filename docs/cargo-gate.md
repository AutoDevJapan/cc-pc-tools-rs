# Cargoの共有ビルド枠

同じ生成先はこれまでどおり排他する。生成先を確保してから、マシン全体の枠を取得する。生成先の待機中はマシンの枠を使わない。

ゲートは受付のたびにWindowsのCPUカウンターを250ミリ秒間隔で測り、空き物理メモリも読む。CPUが75%未満で、空きメモリが16GiB以上なら容量を1件ずつ増やす。通常の上限は論理コア数÷4（最低1件）で、32コアなら8件。CPUが90%以上または空きメモリが16GiB未満なら、新しい受付を待たせる。75〜90%の間は実行中の件数から増やさない（実行中が0件なら1件まで受付）。過去に増やした容量は、今の負荷での増枠に使わない。受付後は2秒間、次の受付を待たせ、同じ負荷の測定値による集中起動を防ぐ。すでに動いているCargoは中断しない。

新しく始めるコマンドの並列数は「論理コア数÷実行中のビルド数」と設定の上限（通常10）の小さい方にする。利用者が指定した小さい並列数は保つ。Cargoとnextestの明示引数・ビルド環境変数・テストの並列数にも適用する。実行中のCargoの並列数は、そのコマンドが終わるまで変わらない。設定の並列数は1〜10で指定する。入れ子のCargoは親の枠と並列数を引き継ぐ。

設定はロックのフォルダーにある `cargo-gate.json`。通常は `D:/CC/Tools/codex-jobs/cargo-gate.json`。環境変数 `CODEX_JOBS_CARGO_SLOTS` は使わない。設定ファイルは待機のたびに読み直すので、起動済みの新しいゲートにも変更が届く。ファイルが無ければ次の値を使う。

```json
{
  "max_slots": null,
  "jobs_per_build": 10,
  "test_threads": 10,
  "min_free_memory_gib": 16,
  "grow_below_cpu_percent": 75,
  "pause_at_cpu_percent": 90,
  "settle_seconds": 2
}
```

ジョブと同じフォルダーの `queue-config.json` でも、`cargo_slots`、`cargo_jobs_per_build`、`test_threads` を指定できる。指定した項目だけが `cargo-gate.json` より優先する。省略またはnullなら共有ゲートの設定に戻る。ビルドとテストの並列上限はそれぞれ1〜10。実際の並列数は、その上限と「論理コア数÷受付時の実行中件数」の小さい方になる。受付のたびに両方のファイルを読み直す。ジョブの同時起動上限や `fixed_max_running` とは別の設定である。

例えば32コアのPCでビルドを2件・各8並列に制限するなら、`codex_jobs.exe update-queue-config --patch-file <JSON>` に次の部分更新を渡す。2件×8並列で論理コア数の半分となる。指定していない場合は上記のCPU・メモリによる動的な方針を使う。これは後のPCルールで採用した方針であり、常時2件へ固定するものではない。

```json
{"cargo_slots": 2, "cargo_jobs_per_build": 8, "test_threads": 8}
```

nextestはテスト用の明示引数と環境変数をテスト上限に収める。`--build-jobs` はビルド上限に収める。`cargo test` は `--` の後の `--test-threads` を制限し、指定がなければ追加する。1並列など、小さい明示値は維持する。`--no-run` はテストを実行しないため引数を追加しない。入れ子のCargoはビルドとテストそれぞれの親の上限を超えず、現在の設定でさらに制限できる。

`max_slots` がnullならコア数÷4、数値なら指定値と論理コア数の小さい方が上限になる。設定を変えるときは一時ファイルに完成したJSONを書いてから置換する。設定が壊れている、読めない、または負荷を測れない間は、理由を表示して待機し、読み直す。スケジューラーとゲートは同じ設定の検査を使う。容量の記録は補助情報であり、壊れている・読めない・保存できない場合も、その場の測定値と使用中のロックで受付を判断する。

受付の確認と枠の確保は、マシン全体の受付ロックで順番に行う。従来の `cargo-build.lock.N` のバイトロックを継続し、旧版が使用中の枠も数える。設定を下げた後も、上限より大きい番号の使用中の枠を数える。ロックはプロセスが終了するとOSが解放する。受付結果は `cargo-admission-state.json` に原子的に保存する。空きメモリ不足とCPU高負荷の待機は、枠の不足と別の理由を表示する。記録を保存できない間は、受付後の2秒の待ち時間を共有できない。CPU・メモリの閾値と、生成先・全体の枠の排他は維持する。

実行ファイルを差し替えても、すでに起動している旧版のゲートは旧版の処理を続ける。新たに起動するゲートから動的受付になる。旧版と新版が混在しても生成先と枠のロックを共有する。実行中のビルドを止めて一斉に再起動する必要はない。

回帰テストはCPUとメモリの境界、8件の受付、並列数の配分、設定の再読込、上限を下げた後の占有、旧版のロック、集中起動の抑制、同じ生成先の排他、待機理由と終了コードの維持を確認する。

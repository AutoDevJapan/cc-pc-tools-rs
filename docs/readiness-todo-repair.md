# 共有ToDoの混在したジョブ参照を読む修復（2489）

親2488の無人運用点検から分担した作業。担当の変更は `cc-todo/src`、
`cc-todo/tests` とこの文書に限る。共有worktreeに直接変更し、個別の
コミットは作っていない。Discordとスケジューラーの変更は親が統合する。

## 確認した問題と修正

実台帳の2,491項目には、ジョブ欄のオブジェクト27件が8項目に混在していた。
旧実行版の `list` は文字列への強制変換でpanicし、終了コード101になった。
配列内にはジョブIDの形式を満たさない文字列も8件あり、合わせて15項目に
未確認の参照がある。これらの元の内容を表示したり、消したりしていない。

`job_refs` は既存のcc-jobsと同じ、空でないASCII英数字・ハイフン・
アンダースコアのIDだけを参照する。オブジェクトの `id` や承認らしい値を
有効な参照へ変換しない。配列以外の壊れた欄も、一覧では未確認件数として
示す。元のJSONと未確認の状態は保持する。

一覧は最後の有効な文字列IDから作業場所を読み、未知の内容は件数だけを
示す。`job_cwd` は不正なパス要素を読み込まず、`start --job` は不正なIDを
状態更新の前に拒否する。復旧処理も同じ参照の取り方を使い、未知の値を
担当の所有や過去の有効なジョブとして扱わない。保存された実行仕様がない
未着手項目について、オブジェクト内の値から仕様や実行許可を作らない。

# 現在の実担当と元の質問の対応

元の質問番号と現在の実担当が異なる現在の受付を、過去の委譲関係の復元と分ける。
今回の有限な対応は元3264・実担当3350・修復依頼4084だけとし、既存1171/3277の
再開確認は変更しない。画像の保護確認や生成証拠に例外を追加しない。

通常askのcontrollerは、正規received-input APIで現在の担当と修復依頼の
受領済み入力を再照合する。固定した仕様版、実ジョブ、登録project/root、
実作業場所、GitのremoteとAPIのrepository IDを比較し、元仕様と担当仕様の
現在のSHAを結び付けた記録を質問予約前に不変保存する。
入力APIのparent_edge=nullをそのまま保持し、新しい記録を過去の委譲edgeや
本人性・画像資格の証明へ変換しない。worker作成のmanifestやnoteの数字、
waitの依存関係だけを受付の根拠にしない。

元番号、本文、題名、判断identity、添付SHAと要求IDは従来の質問予約で保持する。
現在の実actorは送信identityに混ぜず、回答配送先として別に保存する。
無関係actor、別project/root/repository、仕様差、本人停止、guard拒否は維持する。
RustのToDoロック内でも元行・両仕様・登録rootを照合する。

対象リポジトリは依頼どおりprivateを維持し、元trackerは担当の完了待ちを保つ。
公開化やtrackerの別用途への変更を、この修復で許可しない。
予約中に担当のjobが正常に変わっても、元の予約証拠はjobと入力版のanchorだけに使う。
現在のAPI資格は毎回確認し、保留・停止した担当に予約証拠で送信や待機を許可しない。
APIが再照合したspec・dispatch・受領本文のバイト版が同じ場合、登録情報の補助hashの
変化だけで元質問の不変証拠を作り直さない。入力版が違えば引き続き拒否する。
予約中の保留・停止による拒否は、通常CLIでは固定stageの`actor_scope`として返す。
実入力による時間計測は予約前と送信前の資格確認2周を対象とし、保存済み証拠の
ディスクSHA照合・実画像のアップロード・実配送を含む計測とは区別する。

受入条件は、通常askの同じ再試行が一つの画像質問へ戻り、元のtrackerと
担当の依存を保持し、本人回答の全文・本人ID・質問世代を正しい両記録へ保持すること。
画像の配送、画像への本人回答、UI実装は別の完了条件とする。

合成テストのRed/Green、影響するGo/Rustと正規ToDo CLIの結合テスト、
別モデルレビュー、CI、通常マージ、既存writerと直列化した配布、実送信を確認する。
私的な本文・画像・製品の内容と実測結果は公開Git/CIへ保存しない。

# 全候補の処理を続けるための実行設計

元3048の新規4・既存10、原本とバックアップを保持し、指定16資料の全候補から
有用なSkillsを広く導入する。評価の公開やPR作成を依頼全体の完了とはしない。

小さな評価群ごとにカウンターと検証を複製する方法を改め、
[共通の受領・継続処理](skills-3080-received-evidence-acceptance.md)へ移す。
[固定入力表](skills-3080-execution-evidence.json)と
[実行結果](skills-3080-execution-queue-summary.json)は全出現を同じ状態モデルで追う。
本文が同じでも出典・個別許諾・支持資料の範囲は別に確認する。
候補ごとのToDoを作らず、元3080の同じ処理待ちから有限な入力群を進める。
群の大きさを導入件数の上限にしない。

処理待ち一覧とsummaryは同じディレクトリの一時ファイルへ書き、同期・close後に
上書きしないhardlinkで公開する。未完成の一覧を最終名へ書かない。
summaryを最後の完了記録とし、一覧の実SHAとの対応が揃うまで完了ではない。
二つの公開は一つの原子的な操作ではない。間にプロセスが止まった場合は、
同じ入力から再生成した完全な一覧と既存一覧のSHA・size・実体が一致するときだけ
欠けたsummaryを公開する。異なる既存ファイルは保持して失敗とする。

次に進める対象は、既に評価した候補の採否・改訂・正常な新規配置、
受領済み結果の統合、未評価本文と個別条件の調査に分ける。
原文を再読した担当、伏字付きの読了、差分比較、同一noticeの再利用、走査、部分読取を
混同しない。実読記録が無ければ、同一hashだけで読了を増やさない。

# 期限をまたいでも同じ割当検査を行う

PR328のマージ後検査39520384110は1306件中1305件成功し、
`only_original_review_changes_and_history_is_complete`の再実行確認だけが失敗した。
固定割当の期限1792540800（2026-10-21 09:00 JST）を実時計が過ぎ、
正常な期限切れ拒否を、検査が期限前の無変更成功と期待していたためである。

通常CLIの`allocate_review`は期限・停止・資格・ロックの検査を維持する。
既存の`bind_review`も実時計を使い続ける。内部の時刻判定を
`bind_review_at`へ分け、検査だけは固定の観測時刻を渡す。
環境変数やCLIの時計上書き、期限の延長、実台帳の変更を追加しない。

受入条件:

1. 元の検査が実時計の期限到達により失敗することをRedで確認する。
2. 固定した期限内の時刻で、同じ割当の再実行が無変更となる。
3. 期限直前は無変更成功、期限ちょうど・直後は無変更で拒否する。
4. 実行入口は実時計を維持し、他の停止・資格・依存の条件を変えない。

対象はcc-todoのproduct_review結合検査と、同じ処理のClippy/doctest。
別モデルmaxでこの小差分を確認し、必要CIと通常mergeを確認する。
既に実施した元3126の担当回収・scheduler配布・3050/3070の移行は再実行しない。

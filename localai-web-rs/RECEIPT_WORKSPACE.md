# 担当受領を保った作業場所の復旧

消失した旧スケジューラーの作業場所は復旧先を固定しない。保存済みの待機場所、作業場所、元の担当記録、登録先を順に照合し、実在する正当な場所を選ぶ。読取拒否やファイル種別の誤りは不在に置き換えない。

動画などの成果を保存する作業場所は登録されたツールのフォルダーと異なる場合がある。終了した担当が元ToDo番号（又は明示された関連番号）を持ち、元ToDoにもそのジョブの受領リンクがあり、実在する同じフォルダーを指す場合だけ、Git管理のない成果フォルダーをその場で引き継ぐ。登録先の祖先に当たる広い作業場所を成果の所有とみなさず、登録先へ戻す。元フォルダーはコピー、削除、リセットしない。除外対象と完了・判断待ち・依存待ち、実行中の担当、CPU・メモリ・起動間隔の検査を維持する。新しい会話を使い、古い会話を同時に再開しない。

復旧判定の版を照合証拠へ保存する。旧判定で止まった受付は、版の変更後に同じ予約・本文・起動識別子を再評価する。新しい同内容の依頼を増やさない。

回帰検証は、旧作業場所の消失、正規の登録外成果フォルダー、受領リンクの欠落、異なる担当番号、実行中の担当、違うフォルダー、広い祖先、除外対象を扱う。受付の成功は実作業の開始とは区別する。

# 所有付き一時フォルダーの退避

## 元担当の利用解除を既存の清掃へ渡す

新規createは、正規の実行中ジョブを確認できた場合にv3で元ジョブ・元ToDoと
祖先のvolume/file IDを残す。通常planの512MiB上限と別execへの提出は従来どおり。

元担当だけが、特定IDの作業終了・不要・保持なし・依存なし・再生成可を
`safe-delete.exe release --id <ID> --disposable`で記録する。旧v2の原受領を検証する
場合は`--producer-job <元ジョブ>`、旧退避の原受領には`--move-job <退避ジョブ>`も使う。
これらは正規ジョブを探す手掛かりであり、証明ファイルの登録や所有の付け替えではない。
create/release/quarantineは、それぞれ単独の通常CLI呼出しで出力を受領する。
echo、複合コマンド、出力欠落、失敗、重複出力は原受領として受け付けない。

releaseは同じ元ToDoの実担当だけが行える。元のcreate出力・現在の仕様と保持指示・
Gitの未コミット/未push成果・現物のリンクと全一覧を照合する。元ToDo全体の完了は
条件にも証明にも使わない。再生成できないもの、必要なソース/記録が混在するものは
通常の清掃へ渡さず保持する。解除を新しいcollectorが自己申告する機能はない。

既存Rust cleanup-8hは`cleanup-lease --path <既存退避先>`を子として呼ぶ。
Goは原受領・元ID・現状態・一般guard・同一実体・全項目を照合し、元IDのOSロックを
保持して有限な計画だけを返す。Rustがpayloadだけを処理し、成功後にfinishを返す。
原receiptは`quarantine_removed`となり、理由と証拠の親フォルダーは残る。
退避先索引や手編集したreleaseだけでは候補にならない。資格失敗時に汎用削除へ
戻さず、未測定の容量と0バイトを区別する。新しい監視/定期タスクは作らない。

`inspect-retired --id <ID>`はcanonical storeを読むだけで、実物を動かさない。
仕様、旧v2の制限と受入は[ToDo3757](../docs/owned-retirement-3757.md)を参照する。

## Consoleの画面テストで作成した一時データ

今回の元の作成記録に一致する所有IDだけを、`quarantine --id <ID> --reason windows` から保全付きで退避する。通常のplanと他のGit保護は変えない。公式GitHubのrun・job・PR・main応答を原文ごとにハッシュ固定し、成功した同じソース、mainへの統合、配布物2件の実ハッシュを照合する。作成記録・所有者・処理の終了・Gitの保存状態・全項目の安定を確認し、元のGit情報を含めた全データを同じCドライブの削除希望へ移す。移動前後の全メタデータ・内部別名・原記録を照合する。削除や別フォルダーの許可は含まない。

この公開リポジトリの通常Windowsテストは、無料の標準GitHub実行機を使う。開始前にGitHubの現在のPR/mainとheadを照合する。非公開のコピーでは既存の隔離されたPC実行機と受付手順を維持する。

PCで配備済みのGo版safe-deleteのソースと既存検査を、このリポジトリーで管理する。
新規道具はGoを使うPCオーナーの指示に従う。通常のplan・quarantine・finishの
所有照合、Git保護、外部ハードリンク拒否、reparse拒否、項目数上限は維持する。
実行ファイルの隣のreceipts-goを使い、既存フォルダーの所有登録は追加しない。

## ToDo3174の終了済みWindows検査資源

固定ID4378ff571926b0ddbec4ed99368a6405の`quarantine --reason windows`だけに、
正規collect後の原記録・source・公開API・全属性一覧・停止SCM・回収marker・
client guardを確認する資格を設ける。既存claim lockを保持し、SDKのopaque reparse
13件のリンク先を読まず、通常Move-Itemの前後で全3,626項目の実体保持を確認する。
原receipt bytesと属性一覧を退避先へ保存し、保持確認後だけ原receiptを閉じる。
planと他のrootの境界は従来どおり。詳しい受入条件は
[有限な退避の仕様](../docs/todo3174-ci-quarantine.md)に記録する。

## 元と同じドライブへ退避する

通常の所有確認と測定を終えた後、退避先の既定値を元のドライブへ合わせる。
Cドライブの対象は従来のDownloads内の削除希望を使い、別のローカルドライブは
そのドライブ直下の削除希望を使う。たとえばDの所有付き一時物はDへ退避する。
ドライブ種別はGetDriveTypeWで確認し、固定・着脱・RAMの各ドライブを対象にする。
ネットワーク共有を割り当てたドライブ文字や不明な種別は、従来の設定先を保つ。
明示された別設定、検査用の退避先、未対応のvolume表記は変更しない。
元の所有記録、Git・リンク・reparseの保護、移動前後の確認と記録処理は維持する。
ドライブが合わない場合の既存の拒否を無効にせず、退避を容量回収とも数えない。

## ToDo2307のGemini試写の一時データ

`quarantine --id daab67bf8e2c4e2e7d805c3cf9a06a6d --reason hardlink`
だけに、完成動画と実体を共有する一時名の保持検査を追加する。
元のplanとquarantineは補助コマンド自身がHARD_LINKを返した。OSや自動承認レビューの
拒否ではない。通常の削除を再実行せず、許可設定も変更しない。

元のGo所有記録のチェックサム、project/content/作成時刻、固定のTemp直下パス、
volume 2229119083、rootのfile ID 9570149211999247を照合する。
固定した1784担当worktreeは読み取りだけ。完成音声・字幕映像・JSONは保持する。
client guardで元パスと固定した完成動画を照合してから、通常ファイルの識別情報を読む。

対象は根の中の13項目・27,518,293 byte。
外部ハードリンクはverified-preview.mp4の1名だけで、固定した完成動画
aoi-full-preview.mp4とvolume/file ID（0x100000003bc801）・サイズ9,536,831 byte・
リンク数2・属性・作成/更新時刻が同じ場合に限る。他の共有名、Git領域、
reparse、内容・識別番号の変化は拒否する。外部の名前を列挙・移動・書き換えない。

全項目の識別番号・相対名・サイズ・属性・時刻・リンク数と、全通常ファイルのSHA256を
保存し、移動直前に再照合する。完成動画も読み取りでSHA256とメタデータを照合する。
新しい同じCドライブの削除希望へ、従来の通常Move-Itemでフォルダーを移動する。
移動後に根の識別番号と全一覧・全内容・完成動画が一致した場合だけ、元の所有記録を
quarantinedへ更新する。退避先にpreservation.jsonと理由.txtを保存する。

実行担当は対象を使うジョブ・書き込み処理が終了していることを直前に確認する。
検査後の同一ユーザーによるファイル置換を防ぐセキュリティ境界ではない。
移動後の検証や記録で失敗した場合は、未完了の理由と両方の場所を残す。
元パス不在だけでfinishして完了へ読み替えず、保存したpreservation.jsonを使って調べる。
自動再移動・別経路の削除・所有記録の作り直しはしない。

```powershell
go test -race -v ./...
go vet ./...
go build -trimpath -o <所有付き検査フォルダー>/safe-delete.exe .
```

公開CIはWindowsで同じ全Go検査・vet・buildを実行する。
試験の共有名はt.TempDir内の架空データだけで、実物の所有IDを登録しない。

# 現在の本人依頼と元の作業を照合して再開する

元3638の現在の再開依頼を、1626、3277、3549、3623の元の登録へ結ぶ有限の修復。
原保護名簿の復旧、期限切れ証拠の延長、本人停止や依存の解除とは分ける。
PR443の起動登録復帰と通常のdispatcherを利用し、別の起動経路は作らない。

本人の原発言は、元のnativeセッションのユーザー発言で確認する。親の引用や
担当への起動仕様を、本人が直接入力した発言やDiscord APIの回答とは扱わない。
元セッションの識別情報、原発言の位置、原バイトのSHA256、日時とroleを照合する。
その発言が具体化された元3638と実装3650の保存仕様も別々に照合する。
原会話と私的な作業本文を公開リポジトリへ保存しない。

各対象は登録project/root、元仕様の原バイト、実所有者、元担当との対応を確認する。
元1626では既存の元依頼・元担当・作業場所の照合を再利用するが、旧APIは引き続き
期限切れを返す。新しい出所の確認を旧証拠の時刻変更で代用しない。
3277は正規部署データとGitHub所有者・repository IDを照合する。
3549の資格は元の起動仕様と担当、既存道具の同一性、独立した担当作業場所だけに限る。
Xの利用データ、Skillsやブラウザへの包括的なファイル許可は作らない。
3623は元のCI用一時フォルダーの所有と終了を別に確認し、通常のsafe-deleteを使う。

新しい確認結果は原発言と元3638を出所として返す。Rust側でも元のrootと現在の
保存仕様のパス・内容を照合する。確認後に値が変わったら通常の再確認へ戻す。
資格確認、登録復帰、起動、実処理、元の業務成果の完成を別に記録する。

受入条件は、原発言のrole/出所/日時/バイト不一致と別対象を拒否し、元の停止・依存・
未完了成果を保持すること。通常の別モデルレビュー、影響範囲のテストとCI、通常マージ、
現用ソースとの並行変更確認を経て反映する。実際に再開した実行IDと処理の証拠を
元ToDo・親3638へ保存し、既存の進捗スレッドへ通知なしで配送・読み返しを行う。

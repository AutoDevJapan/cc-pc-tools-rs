# 原2191の必須検査二件の予約照合

原2191の要求ハッシュを返す修復の必須検査3648/3649は、作業先の資格確認で
起動準備が止まっている。推定した作業先を作る前に、保存された実予約との
一致を通常CLIで確認する。同3255の限定診断であり、新しい検査担当は作らない。

## 読取と出力

`record-recovery required-checks-metadata` は引数を受け付けない。既存と同じ固定の
共有ToDoスナップショットを最大64 MiBで一度読み、そのバイト列のSHA256を返す。
対象は3648/3649の二件だけで、所属は `localai-web-rs` と完全一致させる。
本文、題名、私的パス、他項目、認証値、参照文字列とそのハッシュを返さない。

返すのは対象ID、現在状態、実行参照の配列長、仕様参照の有無、schedulerの
容器状態・許可したphase・key参照とselection容器の有無である。
project登録のパスと予約worktreeは値を返さず、文字列が存在し形式が有効なときだけ、
現在の登録先に `-wt/todo-3648-cargo` / `-wt/todo-3649-work` を続けたレイアウトとの
字面の一致を返す。予約branchも、固定の `scheduler/todo-3648-cargo` /
`scheduler/todo-3649-work` との一致だけを返す。

パスの字面比較は区切り文字と大文字小文字をそろえるが、ファイルシステムを
開かず、リンクの解決・Git同一性・所有・資格を検証しない。欠落、null、型不正と
比較済みの不一致を区別する。比較値が不明ならfalseや空へ変換しない。
対象PCの登録形式に合わせ、パスはドライブ文字から始まるWindows絶対パスの
構文だけを扱う。相対パスやUNCなど別形式は不正として残す。
対象欠落・重複、所属不一致、不正JSON、重複キー、読取失敗は固定エラーにする。

この投影は予約を作成・編集しない。worktree、参照先、Git、guard、Consoleのqueueを
開かず、状態・停止・依存・受付・起動資格を変更しない。実行・復旧・検査完了、
保護台帳の復旧、データアクセスや準備の許可は常に未確認として返す。
一致が確認できても、同じ元担当の正規準備と資格確認が別に必要である。

## 受入条件

- 有効な架空snapshotに両予約があるとき、固定二件だけの一致と状態を返す。
  入力に含めた本文・題名・パス・他項目の値は出力しない。
- 予約の変更・不在・null・型不正、project登録不明では、それぞれを区別し、
  未確認を一致や比較済みfalseへ変えない。
- 引数はsource読取前に拒否し、正常な入力では読取を実行して結果を返す。
- 実CLIの分岐、破損・重複・所属違い、許可した全出力キーを合成データで確認する。
  現用の保存ファイルはテストで開かず、既存2191の投影を変更しない。

架空データの成功を、実予約の取得、資格確認、実準備、検査や原2191の完了へ
広げない。実取得は別モデルレビューと同じ最終ソースの正式CIの成功後に行う。

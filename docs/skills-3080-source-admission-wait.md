# 既存のSource要求を保った有限待機

通常のdispatcherが正常終了し、対象IDに結ぶ明示的な未起動を返した場合だけ、
同じcanonical Source開始の中で通常の受付を再確認する。
対象とする理由は実行可能数、優先順位、明示的なbusyに限る。

新しい要求・nonce・保管先は作らず、初回に照合した要求、仕様、発行元、物理IDを保持する。
試行ごとに実担当、保存済み仕様、元のsubwork関係、登録ジョブ列、前ジョブの終了、停止条件、
保管先の物理IDと空であることを通常のmetadataから再確認する。
可変metadataの読み取りハンドルは通常dispatcherを呼ぶ前に閉じる。
依存、優先順位、資源、共有ロックの通常判定は毎回同じdispatcherが行う。

待機の期限は開始処理へ入った時点から180秒で固定し、通常コマンド1回は残時間と90秒の小さい方を使う。
再確認は最大3回、間隔は残時間を超えない5秒とし、確認や起動の時間で期限を作り直さない。
通常の準備・メタデータ確認にも既存の期限があるため、この期限は新しい試行と待機を開始する上限である。
終了時は試行数を記録し、既知の未起動のまま期限・回数を使い切ったことを区別する。

正常な実起動は一度で返し、実行中の対象も再起動しない。
コマンドの異常終了、タイムアウト、不正・欠落・矛盾した応答、未知の未受付理由では繰り返さない。
その場合は最新ジョブと保管先を正常照合し、結果不明の試行を消したり新nonceへ置き換えたりしない。

この制御は新たなSource資格や本文の利用権限を作らない。
正常な起動の後も、入力の記録、原結果の受領、内容の受入、配置、実行中と終了後の利用、
同じバッファによる発見・適用を、それぞれ実結果で確認する。
更新前のソフトは[生成前の観測](evidence/skills-3080-guard-before-source-wait.json)に固定し、
既存準備の発行元は観測済みの完全なhashとrevisionの組だけを移行対象とする。

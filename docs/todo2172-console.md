# 共有担当の再開と終了結果の受領

ToDo2172は、共有ジョブの履歴リンクだけで親の継続を止める問題と、明示再開した項目を古い終了結果で再停止する問題を修復する。

Consoleのソースは、PC内のGitリポジトリ `localai-web-rs` の基準コミット `3b1d556` から、この既存の非公開PCツールリポジトリへ保存した。新しいサービスや公開リポジトリは作らない。依存パスは同じworkspaceの共有クレートを指す。配備先と定期タスクは従来のままで、PC内の元のGit履歴も維持する。

ジョブの明示ToDo番号は、同じ項目の保存済みリンクと照合する。番号のない古い共有ジョブは、未完了の項目と保存済みの子から親への依存を確認する。終了した子の古い担当記録だけで親を置き換えない。現在の担当受領は再開世代を照合する。無関係な複数の根拠や循環は保留する。名前や作業フォルダーから親番号を推測しない。

受付の本文・指紋・指定権限と実行の受領は別々に保存する。連携ツールの結果を受け取れない場合は、同じ起動識別子の実ジョブを先に照合する。構造上の失敗は同じ処理を5分ごとに繰り返さず、元仕様、担当、登録したプロジェクト、作業場所の所属、変更の保存状況を再確認する。修復根拠が変われば同じ受付を再評価する。他の独立した受付は進める。

元の広いTools/ADJフォルダーで起動した記録があっても、その全体を新しい作業場所へ複製しない。明示ToDoが登録された製品の原本から作業する。古いフォルダーと未コミットの変更は維持する。レビューの権限は実装の権限へ拡大しない。

共有CLIの `edit --note-file` と `edit --spec` は、項目の状態・担当・進捗・依存を変更しない。旧メモと旧仕様の保存先を履歴へ残し、同じ内容を繰り返しても履歴を増やさない。終了結果の処理済み記録、明示再開の世代、最終反映前の共有OSロック内での照合は [受領と編集の仕様](todo-resume-edit.md) を参照する。

完了済み作業、オーナーの停止・判断待ち、未完了ToDoへの依存待ちは維持する。Consoleの予約を削除せず、新しい監視や並列制限を追加しない。共有枠の容量とCPU/RAM/ディスクの検査は従来のものを使う。

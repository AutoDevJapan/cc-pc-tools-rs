# ToDoの明示再開と履歴を残す編集

## 終了結果を一度だけ反映する

`processed_results` はToDoごとのジョブIDをキーにした永続記録で、反映した結果または担当交代で失効した結果を記録する。同じジョブが複数のToDoを担当しても、受領はToDoごとに独立する。状態変更と受領記録は `todo.lock` のOS共有ロック内で、同じ `todo.json` の原子的な置換として保存する。

`todo start <id> [--job <id>]` は `resume_generation` と `worker_receipt` に明示再開の世代と担当を記録する。scheduler欄がない項目でも担当の受領を記録する。同じ担当でdoingのまま同じ受領を繰り返す場合は世代を増やさない。blockから再開する場合は同じ担当でも世代を増やす。`--job` なしの再開も世代を増やし、結果を読んでいる途中の古い巡回を失効させる。

旧形式の `scheduler.phase=finished` は結果反映済みとして扱う。再開時にも旧結果を永続記録へ移し、再適用しない。`--job` なしでは終了済み担当を `last_job` に残して現在の担当から外す。実行中の担当は維持する。指示書、担当履歴、作業場所、回答、進捗は保持する。

結果の読取後、保存直前のOS共有ロック内でdoing・担当を含むscheduler欄・再開世代・待ち先・未受領を照合する。読取中のStart、Block、Waitに古い結果を上書きせず、失効した処理は更新時刻も変更しない。オーナーによる停止や未完了ToDoへの依存待ちは従来どおり保護する。

## メモと指示書の編集

```text
todo edit <id> --note-file <UTF-8ファイル>
todo edit <id> --spec <UTF-8ファイル>
todo edit <id> --note-file <UTF-8ファイル> --spec <UTF-8ファイル>
```

少なくとも片方の指定が必要。空の本文、無効なUTF-8、1 MiBを超える入力、読取失敗は保存前に拒否する。BOMと改行は指示書追加時と同様に整える。両方を指定した場合も全入力を検証してから更新する。

状態、担当、依存先、進捗、自動実行の許可、他の項目は変えない。変更したメモの旧値と旧更新時刻は `note_history` に残す。指示書は `specs/<ToDo番号>-<UUID>.md` に新しくコピーし、旧保存先と旧更新時刻を `spec_history` に残す。旧ファイルは変更・削除しない。旧保存先のファイルがなくなっている場合は新しい指示書で修復できる。旧ファイルのUTF-8不正や権限エラーは保存前に拒否する。

現在と同じ本文を繰り返し指定した場合、履歴・保存先・更新時刻は変えない。保存は既存CLIと同じ共有ロックと原子的なstore置換を使用する。指示書コピー後にstore保存が失敗しても、storeと旧指示書は保持される。未参照の新しい指示書が残ることはあるが、再実行で既存ファイルを上書きしない。

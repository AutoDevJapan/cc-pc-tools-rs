# 保護判定の範囲（ToDo3258）

## 本人が指定した範囲

保護とは、プログラムが対象の読み取り・利用を止める判定を指す。
本人が指定した保護対象は、受託案件と本人のクレジットカード情報の二種類である。
新しい支出の禁止は操作の条件であり、ファイルの第三の保護分類にはしない。

出所は2026-10-21の正規Discord APIによる本人の返信。本人確認済みの原記録は
親3110が保持する。本仕様には原資料、案件名、カード情報、返信全文を載せない。
同日の権限方針の正本はPC内の `D:/CC/Policies/owner-agent-conduct-20261021.md`。
元のChrome整理の停止は変更しない。

## 現在の問題と変更

従来の `client_resource=true` は、受託案件との一致だけでなく、列挙済みの
修復範囲に入らない場合にも返される。未知の対象を受託案件だと断定するのは誤り。
一方、分類できない対象を、本人の新しい方針だけで安全だと断定することもできない。

通常の `--guard-path` に、確認できた保護分類と分類未確認、利用可否を分けた
メタデータを加える。旧利用側の停止を保つため、従来のbool項目は互換性を維持する。
出力にはパス・案件名・秘密値・原台帳の内容を含めない。
`original_registry_recovered=false` を維持し、消失した原本を作らない。

自社のソースは、ToDoに登録済みのルート、物理パス、Gitの共通管理先、
origin、GitHubの実所有者とrepository ID、追跡対象を通常経路で照合する。
部署の正規データ `localai-web-rs/src/operations.rs` の `DEPARTMENTS` で
受託部に一致する添字を求め、一致がちょうど一件でなければ生成を失敗させる。
`operations_catalog.rs` の全製品宣言から、その添字を使って
名前を公開しないハッシュの照合データを `go generate` で生成する。
受託部との一致を優先し、自社所属を確認できない登録は許可しない。
三所有者の配下という理由だけで自社とは判定せず、別製品として指定された
repository IDの区別も維持する。個別のToDoやファイルの例外追加ではない。
この分類にToDo番号・個別ファイル・期限・担当の枝名の追加列挙を使わない。
判定は依頼の実行許可・起動許可ではなく、停止・完了・依存・本人の指定範囲を変更しない。

カード情報を表す可能性があるデータ名・格納先は、内容を開く前に未確認として止める。
名前だけでは本人の実カード情報があると確定せず、保護確定のカテゴリを捏造しない。
認証ファイルやGit管理領域、未追跡の未知データを、新しい自社ソースの資格だけで
読めるようにしない。既に用途を確認した運用経路へ一律の禁止を追加しない。
カードを扱うソースコードの名前、契約額・周期等の非カード情報、許可された
公式テスト用データを、本人の実カード情報の禁止へ含めない。
名前を使うカード候補の判定はデータ・文書とリポジトリ外の格納先に絞り、
コードの葉のファイル名を実カード情報と断定しない。カード候補の格納先の下に
コード拡張子があることを格納先の確認の代わりにはしない。
日本語の濁点・半角表記も正規化する。Git追跡だけを根拠に、出所を確認できない
カード候補のデータを安全と判定しない。公式のテストモードと確認済みのテスト用データを
禁止するものではなく、このファイルの内容の出所が未確認であることと区別する。
カードの値を探すための内容走査はしない。名前からカードだと確認できない未知の
データも分類未確認のまま止める。既存の除外との一致は自社所有者確認より優先する。

## 入出力と失敗時

- 入力: 通常の `scrub391 --guard-path <絶対パス>`。
- 出力: 既存のboolと、`access_allowed`、`protection_status`、
  `protection_categories`。カテゴリの値は `client_project` と
  `owner_card_information` のみ。未知はカテゴリを捏造せず `unverified` とする。
- 互換項目 `client_resource` は従来どおり「利用を止める」値。
  `classification_unverified=true` との組合せを受託案件の確定と解釈しない。
- 原台帳の欠落・破損、登録不正、リンク、Git/API不調、所有者不一致、
  未追跡ファイルは新しい分類許可を生まない。原台帳の復旧とは別に、既存の
  検証済み修復経路と、照合できた自社ソースの分類は利用できる。
- 原台帳・ToDo・質問・停止・配布先・ブラウザを変更しない。
  会話記録の元ルートの資格は従来の修復範囲を維持し、自社ソースの追加資格へ広げない。
- 読めるソースが増えると、停止されていない依頼が起動候補になる場合がある。
  明示停止は分類とは別にToDoの状態で保持し、配布前後に元3129の停止を確認する。

## 呼び出し時間と実所有者の確認

追加したソース資格の判定は750msで打ち切り、ネットワークを待たない。最初にGit管理の
印を属性だけで確認し、未知の通常フォルダーではToDo・Git・APIを使わない。
登録台帳は一度だけ走査し、projectsだけを保持する。itemsのオブジェクトと配列を
組み立てず読み飛ばす。ファイルのネイティブIDを取得して読み取り後すぐ閉じ、
Git/API照会中に通常の原子的な書換えを妨げない。
最後に同じID・サイズ・更新時刻を確認し、通常のファイル置換や観測できる変更があれば
未確認を返す。これをトランザクションや、任意の原地変更・復元がなかった証明とはしない。
無関係のメモ更新であっても照会中にファイル世代が変われば、次の通常照会へ回す。
64MiBという従来の台帳上限も、この読み取りへ引き継がない。

所有者とrepository IDは通常OAuthのGitHub CLIで取得する。確認結果は同じWindows
ユーザーのDPAPIで保護し、正規の部署データと結び付けて最大5分だけ再利用する。
平文の手編集で資格を追加する仕組みにはしない。追加した通常ソース資格のAPI呼び出しは0回。
期限切れ・未確認は分類未確認を維持し、ローカルの資格確認を終えた対象だけについて
最大8秒の非表示の補助処理を1回起動する。常駐・巡回ループ・Codex子ジョブは作らない。
既存の次回の通常判定で結果を読み直す。全体の同時要求を短い所有マーカーで抑止し、
補助処理が消失した場合も20秒後から同じ通常入口で再試行できる。
失敗したrepositoryとカタログの組合せは、時刻を保存して5分間再起動を抑止する。
後始末は自分の要求IDと一致する印だけをハンドル経由で消し、別の世代の印を消さない。
成功した所有者情報は240秒から期限内の結果を返しながら更新を頼み、300秒を過ぎれば
未確認とする。未追跡のファイルは所有者の更新より前に止める。
`--refresh-owner-source <登録済み自社のパス>` は同じ有限なメタデータ確認を明示実行する。
原台帳の復旧、保護の例外登録、停止解除、ソースの内容の読取には使えない。

リンクの実体はファイルの内容を開かず、Windowsのハンドルで最終パスを確認する。
Git照会では継承した `GIT_*` を除き、別リポジトリの索引やoriginを持ち込まない。
根拠: [最終パス取得](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getfinalpathnamebyhandlew)、
[文字の正規化](https://learn.microsoft.com/en-us/windows/win32/api/winnls/nf-winnls-normalizestring)、
[Windowsユーザーによる保護](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata)。

## 受入条件

1. 架空のカード候補の格納先を、修復用ソースの資格があっても未確認として拒否し、
   ファイル名だけから本人の実カード情報だと断定しない。
2. 架空の受託案件と原除外の一致は自社資格より優先し、値や名前を出力しない。
3. 未知を拒否しながら、未知を二分類のいずれかへ断定しない。
4. 正規の部署宣言からの所属、登録、実所有者・ID・Git・追跡対象を確認した自社ソースは、
   個別のToDo例外を足さずに通常判定を通る。
   通常ルートとworktree内の追跡ファイルを実測し、通常の呼出しで期限内に通ることを確認する。
5. 他所有者、受託ID、偽のorigin、別のGit管理先、未追跡データ、認証ファイル、
   リンク、破損登録、API失敗は許可しない。
6. 旧APIの拒否・既存検査と原台帳未復旧の表示を保ち、停止した元作業を再開しない。
7. 別モデルMaxのレビュー、影響範囲のCI、通常マージ、最新マージ版の配布、
   配布物SHA256と正規判定の読み返しを保存する。
8. 元質問への説明は3259の正常入口を使い、無通知・新質問なしで送る。
   送信・読み返し・質問の終了を親3110へ返す。原資料は公開しない。

検査は `repair-guard` の合成fixture、`go test -race ./...` と `go vet ./...`。
判定プログラム以外の挙動を変更しないため、Rust全体のビルドは追加しない。

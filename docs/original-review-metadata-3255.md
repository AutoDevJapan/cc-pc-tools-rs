# 元レビューの来歴を一件だけ読む（3255）

Issue: https://github.com/AutoDevJapan/cc-pc-tools-rs/issues/432
追加のsource参照照合: https://github.com/AutoDevJapan/cc-pc-tools-rs/issues/435

原レビューの受付と、復旧後に付いた依存の来歴を、通常一覧の状態表示だけでは照合できない。
既存の `record-recovery` に `review-metadata` を追加する。入力の対象は元2191に固定し、
他の番号・入力ファイル・出力先・認証設定をCLI引数では指定できない。

## 入出力

- 入力は固定された現在の共有ToDoスナップショット一件。64 MiBを超える読取、壊れたJSON、
  重複キー、重複した対象番号、対象の所属不一致は固定のエラーコードで失敗する。
- 出力は元2191の状態、依存番号、実行参照配列の長さ、復旧メタデータの原番号・確認済み状態、
  登録された根拠のSHA256、時刻、参照の有無だけ。本文、題名、私的パス、未知の文字列、
  他項目の内容を返さない。読んだ同じバイト列のSHA256を添える。
- 参照文字列とそのハッシュを返さず、参照先を開かない。復旧のsource参照だけは、
  固定した元request IDの文字列との完全一致・部分一致を区別する。`queue`・`queued`という
  固定語と、`queue:`・`queued:`の接頭語も構文上の事実として区別する。
- source参照が `YYYYMMDD-HHMMSS-ASCIIの英数字・_・-` というジョブ名の構文で、
  日時も正しい場合は日時部分だけを返す。名前のラベルとパスは返さず、タイムゾーン・
  ジョブの存在・実際の開始は未確認とする。文字列や構文の一致は参照の同一性の証明ではない。
  現在のConsole待ち行列を読んだ結果とも混同しない。
- リンク拒否と実体比較は観測時点の検査。同じ利用者による並行した祖先・ファイル・
  ハードリンクの差替えを、原子的に防ぐ保証はしない。
- 現在の依存配列、更新時刻、メモは、依存を付けた遷移の証明ではない。
  このスナップショットだけで遷移の出所を確定できないことを明示する。
- 不在・null・型不正を区別する。取得失敗を空の原記録や復旧成功として返さない。

## 無変更の条件

状態・停止・依存・元仕様・受付・起動資格を更新しない。参照ファイルの読取、バックアップ、
出力ファイルの作成、ネットワーク、認証値の取得、通知、担当起動を行わない。
元2467の自動起動保留を解除せず、この一件の来歴取得をその全体再始動に依存させない。
この機能は保護台帳の復旧、閲覧資格の付与、原レビューの実施・受入ではない。

## 受入テスト

1. 架空の対象記録から所定のメタデータだけが返り、他項目・本文・私的パスは含まれない。
2. 参照先を開かずに存在するフィールドを示し、空の実行参照と型不明を区別する。
3. 不正な入力、重複キー・番号、上限超過、取得拒否は秘匿した失敗を返す。
4. CLIの任意引数は原記録の読取前に拒否する。入力バイト列と既存ファイルは不変。
5. 現在の依存や更新時刻から、遷移の出所・許可・レビュー完了を作らない。
6. 元requestの完全一致と囲み文字のある部分一致、ジョブ名の日時、不正な日時・パス・
   非ASCII名を区別する。参照の文字列・ハッシュ・ラベルを漏らさず、同一性の確認へ昇格させない。

Goの関連テスト・race・vetと、同じ最終ソースの正式CI・別モデルレビューを確認する。
実データでの実行と配布は、その結果と実行物のソース対応を確認した後に記録する。

原レビューの来歴取得・復旧・実レビューの成功を、架空データで得たテスト結果へ加算しない。

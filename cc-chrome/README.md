# Chromeのタブの後片付け

## 作成結果から個別終了へ進む（Issue #308 / ToDo3129）

`owner_chrome open <job-id> <url>` の成功JSONは、所有記録と同じ
`job`・`instance`・`generation`・`session`・`turn`・`tab`などに加え、
`record_id`を返す。これは作成時に永続化した記録ファイルのUUIDであり、
別のIDを推測したり、記録フォルダーを列挙したりする必要はない。
工程終了時は、この値をそのまま `owner_chrome close <job-id> <record_id> <根拠>`
へ渡し、closed・gone・kept・failedを確認する。

記録の保存が失敗したときは成功JSONを返さず、既存の取消しと再試行記録を維持する。
ライブラリの`open`・`open_until`は従来どおり`Record`を返す。
追加の`open_with_receipt`がCLI向けのUUID付き応答を返す。
所有照合と保持指定の規則は変えない。

模擬pipeの受入検査では、作成した記録のUUIDと応答の一致、接続前の永続化、
返されたUUIDによる1枚だけの工程終了、ほかの作業中タブの保持を確認する。
本人のChromeや実タブをこの検査の代用にしない。

保存済みグループの整理は別の未完了条件である。タブと開いているグループの不在だけを、
保存済みグループの不在と報告しない。現在の記録はタブの作成成功を追うものであり、
グループの作成所有・保存済みグループの削除を記録しているものではない。

## 担当が実行中でも工程が終わったタブを閉じる

`owner_chrome close <job-id> <record-uuid> <工程終了の根拠>` は、chrome-tabs（またはchrome-emergency-tabs）の記録を1枚だけ選び、従来と同じ所有照合・close・履歴保存を行う。担当の終了まで待たない。UUIDは記録のファイル名から取得する。URLや画面の名前で所有者を推測しない。他のタブには適用しない。

先に記録の全identityを含む終了要求を保存する。接続失敗や保存失敗はfailedとして返し、既存の毎分sweepが担当の実行中でも再試行する。closeの成功はclosed、既に無いことの確認はgone、必要なタブはkeptに分ける。実行中の記録にも読み取りだけの照合を行い、既に無いタブの記録を整理する。照合失敗から不在を推測しない。

オーナーが残すよう明示した納品タブは `owner_chrome keep <job-id> <record-uuid> <オーナーの指示>` で記録する。keepは担当終了後のsweepでも保持し、closeは拒否する。直近の工程で使うタブはclose要求を出さず保持する。finishで実行中の担当のタブを一括終了しない。

ブラウザ操作の工程が終わるたび、作成記録とinventoryのinstance・generation・tabを照合し、不要になったものだけcloseする。終了・失敗経路でも結果を確認する。新しい監視ループやChrome全体の終了は不要。

## 検査接続が切れた自作タブの終了

Chromeの検査接続が終了しても、中継側に接続済みの状態が残ることがある。
終了命令が `Debugger is not attached to the tab with id: …` を返し、そのIDが
所有記録のタブと完全一致する場合だけ、同じタブの接続を1回作り直す。
別タブのエラー、権限エラー、取得失敗ではこの復旧を行わない。
復旧中と終了前後にChromeの識別子・世代を照合し、不一致では履歴へ進めない。
終了後の全タブ一覧から対象が消えたことを確認して、終了履歴を保存する。
既存の毎分巡回を使い、新しい再試行ループは作らない。

関連検査は、同じタブだけの復旧、世代変更時の中止、別タブ・権限エラーの拒否を含む。
実機でも残っていた所有済みタブ1枚の終了と履歴・不在を確認した（ToDo #2411 / #2386）。
タブの実ID、ページ情報、認証値はこのリポジトリへ載せない。
接続と終了の公式仕様は [Chrome debugger API](https://developer.chrome.com/docs/extensions/reference/api/debugger) を参照。

# 製品検査を止めるCC側の取消し検査を修復する

Windowsの取消し検査が、数値の親PIDだけが一致する候補を生成時刻の確認前に開き、アクセス拒否で失敗した。原ログには候補の生成時刻がないため、当時の候補が無関係だったとは断定しない。

同時に取得したkernel snapshotの生成時刻と親PIDを用い、親より古い候補をOpenProcessの前に除外する。もっともらしい所有子孫の不明さ、取得失敗、保持した世代の不一致は引き続き失敗として扱う。実際の停止には生成時刻を確認した保持handleを使う。

Native snapshotの親PIDは公開SDK上の予約領域なので、実行時には自プロセスの親PIDを文書化されたToolHelpと照合する。食い違う配置で子孫を見落としたまま進めない。公開APIとの不一致を拒否する回帰も加えた。

元の独立修正1c0ef903ee3dbdc1bd5f7f339fd89ee92500e4b4は、関連52件、全workspace2198件（既存5skip）、doctest、Clippyが成功し、別モデル2723のMustは0だった。全workspaceの実行はそのソースに対して1回で、doc summary16件は全てテスト0件だった。追加した任意の全workspace fmtだけは既存の別crateのimport順で失敗し、成功と記録していない。

親の製品CI修正へ通常mergeした後にToolHelp照合を追加したため、上記旧ソースの検査を最新ソースの成功とは扱わない。最新の同head GitHub CIで再確認する。既存の担当、runner、配布runtimeは変更せず、修復した検査のfixtureだけが停止・回収対象となる。

原ログ、チェックポイント、レビューは元2648の明示されたprivate evidenceへ保持する。子の作業ブランチと元の作業メモは保ったまま、親に取り込んだ古い未接続メモをこの実装記録へ置き換えた。

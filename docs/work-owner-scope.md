# 独立した作業フォルダーと担当の待機（ToDo2269）

登録された作業フォルダーがユーザーのホームGitに偶然含まれても、ホームのブランチを共有する成果待ちにはしない。登録フォルダー内がGitの追跡対象でないことと、実際のGitルートがホームであることを確認し、発見した祖先の情報は証拠として保存する。途中に本物のリポジトリがあれば、そのworktreeを使う。通常のリポジトリでは、未追跡の下位フォルダーでも同じworktreeの書き手を排他する。

同じPR・ブランチの成果待ちは、元担当のプロセスが終了しても対象ToDoの完了まで維持する。作業フォルダーだけの一致は実行中の担当を待つ。終了状態の記録でも、作成時刻が一致する実行中のプロセスがあれば排他を維持する。

キューが記憶した所有待ちには、元担当の正確なジョブ番号・ToDo番号・作業範囲を保存する。再評価で根拠がなくなった待ちは、元の依存と理由を履歴に残して解除する。読み取れない証拠は解除の理由にしない。

ToDoの自動依存には対象番号を型付きで記録する。明示した`todo.exe wait`は自動依存の印を取り除き、手動の成果待ちを保持する。古いToDoで自動依存と証明できないものは保持する。

正規の巡回が自動依存を再評価する。有限の点検は`todo.exe reevaluate-owner-wait <番号>`でも実行できる。このコマンドは該当ToDoの記録だけを読み、ToDoのロック内で保存し、ジョブを起動・取消ししない。案件の除外とプロセスの作成時刻照合を維持する。

配布対象は`codex_jobs.exe`、`todo.exe`、`shepherd.exe`。キューの待機中監視は既存の`reload-queue`で更新する。実行中の担当、ホームの`.git`、別ToDoの成果は変更しない。

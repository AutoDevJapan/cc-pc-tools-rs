# 5掲載の統合記録と台帳の来歴を結ぶ

PR639の固定f131に対するLuna/maxのレビュー4033（実行191115）は、
Must0・Suggestion1・Nit0だった。
個別の統合証拠は検証していたが、台帳を6項目の型へ射影していたため、
台帳側の証拠ファイル名と個別noticeのpath・SHAが変わっても検出できなかった。
実際の5行に不一致はなかった。

担当は自分の作業先で1行の証拠名とnoticeのpathを一時的に別の既知の記録へ変え、
旧テストが成功する反例を再現し、直後に台帳の原バイト列とSHAを復元した。
この反例を公開台帳へ保存・コミットしていない。

検証は、同じ統合証拠を独立固定SHAで確認したうえで、
台帳のID・出典・commit・path・本文SHA・既存統合という処分に加え、
対象Skill・証拠ファイル名・個別noticeのpathとSHA・配置manifest・entrypoint SHAを、
各統合証拠の該当行へ直接照合する。
型への射影で来歴項目を落とす方法をやめ、検証済みの台帳行からだけ採否を返す。

実際の台帳行を使う正例と、証拠名・notice path・notice SHA・manifest・entrypointの
各欠落、報告された別証拠・別folder noticeへの変更を拒否する反例を追加した。
既存の12条件、未知・重複・actor・伏字・未読・全件集計の検証も保持している。

変更後の関連Goテストは実73,220件のqueueと固定snapshotを用いて8.452秒で成功し、
vetも成功した。
元の5掲載とnotice・実読・原応答・採用台帳・queue・既存Skillの本文を変更していない。
新しい許諾・配置・中央書込みは0で、追加差分の別モデルレビューとCIは別に受け入れる。

追加レビュー4033（実行192401）は元の指摘の解消を確認し、
Gitblobとbytesの4項目も照合するSuggestionを返した。
実ファイルを再照合すると、この4項目は個別の統合証拠にあり、
現在の台帳5行には存在しない。「双方に記録済み」という指摘の前提は訂正する。
原台帳に不一致があったとはしない。

同じ領域の指摘が続いたため、来歴の検証を実台帳の必須18項目と、
追加された場合に証拠と一致すべき任意4項目に整理し直した。
出典・対象・個別notice・manifestだけでなく、保持対象、適用範囲、
追加許諾・中央書込みの有無と記録時点の状態も結ぶ。
任意項目がない原台帳を保持し、正しい追加値は許容する一方、
証拠と違う値やnullの追加を拒否する。

原台帳から作る正例、必須18項目それぞれの欠落と改変、
任意4項目それぞれの不在・正値・誤値・nullを確認する。
任意4項目の誤値/nullが旧関数では通る反例8件を、先に失敗するテストで再現した。
この変更でも台帳・統合証拠・queue・既存Skillの本文は書き換えていない。

今回の再開後、同じ最終コードの関連Goテストは実73,220件queueと固定snapshotを使って11.364秒で成功し、vetも成功した。前回のWindows起動エラーはテスト実行前であり、成功したテスト結果へ混ぜない。

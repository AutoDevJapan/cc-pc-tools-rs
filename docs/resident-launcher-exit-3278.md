# LocalAiConsole起動係の終了待ち（ToDo3278）

## 仕様と受入条件

既存の起動係はサービス本体の寿命を待つ。本体が終了した後は、その本体が起動した
別アプリの標準出力・標準エラーの寿命を待たず、既存タスクへ結果を返す。
正常終了は成功、異常終了と起動失敗は既存の `service_process_failed` とする。
正常に稼働するサービス本体には実行時間の期限を追加しない。

元3103では旧サーバーの不在、起動係の待機継続、残る別アプリの親PID、起動係だけの
終了による復帰を実測した。個々の書込ハンドルの保持者を直接計測した結果ではない。
`io.Discard` によるパイプ回収と待機の構造を、検査専用プロセスで再現する。
旧PIDの再停止や別アプリの停止はしない。媒体表示修復の完了条件へ追加しない。

| 条件 | 受入結果 |
| --- | --- |
| 検査本体がstdout/stderrを子孫へ渡して正常終了 | 子孫が存続しても起動係は成功で戻る |
| 同じ構造で本体が異常終了 | 子孫が存続しても有限に失敗を返す |
| 本体が終了の指示を待って稼働中 | 起動係も待ち、本体を時間で止めない |
| 実行物が存在しない | 既存の一般化された失敗を返す |

検査では専用実行物だけを窓なしで起動する。子孫はPID・作成時刻・実行物と所有先を
記録し、終了ファイルで協調停止する。強制回収が必要な場合も、照合済みの保持handle
だけを使い、PID指定のツリー終了をしない。検査データは所有記録付き一時領域へ作り、
生成物の通常plan・別呼出しでの削除・finishを実装担当が確認する。

変更範囲は `resident-guard/service_launcher_windows.go` と直接の検査、この文書。
起動対象、mutex、既存タスク、権限、保護設定、UI、他担当のソースを変更しない。
新しいサービス、タスク、再起動ループを追加しない。

## 検証記録

Issue: [#361](https://github.com/AutoDevJapan/cc-pc-tools-rs/issues/361)。

Red: `go test -count=1 -v -timeout 45s -run '^TestServiceProcess(ReturnsAfterMainExitWithInheritedOutput|RetainsLiveMain|ReportsStartFailure)$' ./...`。
変更前の `io.Discard` を使う同じ起動処理で、正常・異常終了の2条件が期待どおり失敗した。
本体の保持handleで実終了を確認した後も、子孫の出力待ちが1秒の検査期限を超えた。
本体稼働の保持と起動失敗の分類は成功。子孫の協調停止後には起動係も回収できた。

実装前の再現、修正後のGo検査・race・vet、固定ソースの別モデルレビューとCI、
通常マージ、既存Prdの配布と通常再起動の確認は、それぞれ実測後に追記する。

一次資料: [Go os/exec.Cmd](https://pkg.go.dev/os/exec#Cmd)。出力がnilの場合は
null deviceへ接続し、非ファイルのWriterを設定した場合は回収用goroutineの終了も待つ。

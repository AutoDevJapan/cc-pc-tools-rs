# 保存済み手順の評価台帳

[評価データ](skills-3080-retained-procedure-assessments.json)に22件の意味評価を記録する。
固定した出典の本文・支持資料・個別noticeを区別し、未保存や未読の資料を読了へ変えない。
利用許諾の受入・最終採否・中央Skillsへの配置は、この台帳では加算しない。

一次本文はrawの全読記録10件、伏字を含む全行表示の記録12件で、計5,995物理行のうち72行が最終表示で伏字となっている。
表示範囲そのものとそのdigestが公開記録にないため、範囲hashを再計算して確認したとは扱わない。
伏字処理が不十分だった初回表示3箇所は、値を再掲せず位置と種類を保持し、後から「過去も未読だった」と変更しない。

支持一覧320件には一次本文自身も含まれる。
保存済み157件と未保存163件を分け、保存済みはraw全読42件、伏字付き全読23件、同一バイトの既読記録の再利用20件、保存済み未読72件である。
一次本文と支持一覧の読取数は足し合わせない。
支持一覧のSHAとGit blobの短縮値はmetadata照合用で、完全なdigestや個別の許諾を証明するものではない。
個別noticeの出典・完全なSHA・対応する支持記録を別に保持する。

検証器は全件queueへの取込前に、出典とURL、物理行と伏字位置、初回表示の不足、支持の状態とnull、個別noticeとの対応、集計値を確認する。
伏字付きの本文をraw読了へ変える、未保存資料へbyte数を補う、未読の伏字数を0とする、個別noticeから許諾を受け入れたとする等の入力は、artifactのSHAを更新していても拒否する。
記録済みのマスク版は14・16だけを受け入れ、元記録に版の値がないものはnullのまま保つ。
公開データに内部の実行識別子や、ChatGPT・Claude・Discord・Codexの既知の会話URL形式を追加する入力も受け入れない。
URLのhostと復号したpathで判定し、正当なAPI・モデル・ヘッダー名や、公式文書へのリンクだけで生成者の署名と扱わない。

この構造検証だけでは、整合する形にまとめ直された架空の所見や出典の実在を証明できない。
受入では、固定カタログへの所属と完全な出典情報を確認し、保持した原結果・意味読了・実行記録の照合へ結ぶ。
追記時は直前の受入版とそのSHAを起点にし、旧項目の全フィールドと順序、境界条件を比較してから受け入れる。
原結果と担当・再利用の履歴は非公開の原記録に保ち、公開向けの表記整理で変更しない。

既存の進捗にあるraw 588・workflow 807は、以前に定義した構成要素だけの集計で、後続の受領台帳をすべて含む総数ではない。
この22件との重複除去後のraw・workflow総数は、まだ確定値として示さない。
全体の候補数・評価の有無・最終採否は、[全件queueの集計](skills-3080-execution-queue-summary.json)で別に確認する。
同じ本文の評価、候補ごとの文脈と権利、導入済みのSkillを区別し、指定16資料の残作業を継続する。

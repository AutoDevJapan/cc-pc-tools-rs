# 指定16資料からのSkills拡張（元3048、継続3080）

## 要求と現在の許可

代表14件で依頼全体が終わったという旧判断を撤回する。旧3048の新規4件・既存10件とそのバックアップは保持する。指定16資料の全候補から、有用性・個別許諾・重複・本人方針との整合を確かめ、件数上限なく拡張する。本人の方針回答は正規Discord配送の原質問・対象・本人ID・返信版を照合済み。原証跡とSHAは担当の非公開checkpointに保存する。回答は、取得が拒否された647件の再取得を認めるものではない。

作業の単位は元ToDo3080に保つ。候補ごとのToDoは作らない。有限な別モデルレビューは独立した検査として登録できる。担当は調査と実反映の責任を保持する。

## 受入条件

1. 15公開GitHub repoのowner、公開状態、default branch、固定commit/treeと、サイト全索引を追跡する。切詰め・未読・取得保留を全件完了と呼ばない。
2. カタログの各掲載記録を保持し、同一URLと同一本文の関係を別に数える。重複本文でも許諾と出典は消さない。標準Skill、別版、手順資料、デザイン例、prompt資料を区別する。
3. 機械棚卸し、意味審査、許諾審査、候補本文の作成、配置、Codex発見、別モデル受入を分ける。未判定を除外へ変更しない。
4. 採用候補は固定source/path/hash、個別許諾の根拠と適用範囲、本人方針による変更、正例と負例を持つ。原文と許諾原文を保持する。外部資料を実行権限に昇格させない。
5. 新規原本はD:/CC/Skills/<name>/SKILL.md。既存原本とjunction、管理された配布物を保持する。配置先の保護分類が未確認なら書き込まず、具体的な技術保留を保存する。保護確認や実行審査を迂回しない。
6. 既存3048のGo検査器を再利用して構造・参照・ハッシュを確認する。新しいapp-serverのskills/listで発見と解析失敗を確認する。文脈予算は実ターンの観測と分ける。候補作成や索引化を導入済みとしない。
7. 検査と別モデルレビューでMustを解消し、関連CIを確認して通常PRをマージする。有限な単位の達成を全候補の処理完了としない。

## 今回追加した検査

`tools/skills-3080-catalog` は保存済みcatalogだけを読む。HTTP、原本文、外部スクリプト、秘密、中央Skillsは読まない。全掲載記録を新しいreview queueに保存し、本文取得済み・未取得・実行審査保留を区別する。重複ID、壊れたJSON、取得済みなのにSHA256がない入力は失敗する。成功summaryは全入力の解析とqueue出力の完了後にだけ作る。途中失敗のqueueは未完了として保持する。

```text
go -C tools/skills-3080-catalog test -count=1 ./...
go -C tools/skills-3080-catalog vet ./...
go -C tools/skills-3080-catalog run . -catalog <保存済みphase-a-catalog.jsonl> -out <未作成の永続成果ディレクトリ>
```

異なる出典の同一本文、取得失敗、取得拒否、壊れた入力を架空fixtureで検査する。無フラグや重複本文を安全性・許諾の承認には変換しない。これは新規の解析器であり、既存製品の振る舞いを直すRed/Greenの主張はしない。原本配置後の構造検査と実適用は別工程として残る。

候補JSONと採否表はGoモジュールの外にある。これらを変更したときの受入では`-count=1`を付け、以前のGo検査結果のキャッシュだけで更新後の文書を確認したとしない。製品全体の再ビルドは不要。

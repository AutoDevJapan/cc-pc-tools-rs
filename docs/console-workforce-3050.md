## 入出力と表示の契約

1. 入力は常駐側で取得した保護済み共有snapshot。HTTPパネル単位で原ToDo・全ジョブ履歴を再走査しない。
2. 仕事の状態と担当の実行根拠を別に返す。実作業には、担当の識別、最近の思考/ツール/編集/検索などの処理根拠、待機でないことが必要。プロセスの存在・heartbeat・最終文章だけでは足りない。
3. 受付待ち、起動待ち、資源待ち、依存待ち、本人判断待ち、復旧未確認、取得失敗を区別する。queuedの理由がない時は資源待ちへ推定しない。blockだけでは本人判断待ちへ推定しない。
4. 進捗は確認済み整数0〜100かnull。未計測は「未計測/未記録」。更新時刻を最終成果時刻へ流用しない。
5. 各作業は元ToDo、担当セッション、優先順位、現在工程、成果と検査、停止理由、次の一手、Issue/PR/配布参照を持つ。保護中・未登録・未計測の欄は取得不能の理由を表示する。本文を埋めるために原保護名簿を開かない。
6. 取得開始、取得完了、元記録時刻、鮮度、部分取得を区別する。取得失敗時に古いsnapshotを最新と表示しない。未知の件数を0にしない。
7. Native Codex・CC jobs・Claude等の接続範囲を表示する。接続しない経路は未観測とし、全PCの全担当を数えたとは書かない。既存の実作業だけの `/progress` を維持する。
8. UI画像案をDiscordへ直接添付し、方向の回答を反映してから見た目を実装する。実作業優先案と組織図優先案を比較する。新しい製品名は付けない。

# Operations の部署別製品と復旧中の表示

2026-10-12 の本人指定は `localai-web-rs/src/operations_catalog.rs` を正本とする。
GoDD 9製品、自社サービス12製品、ゲーム2製品、受託3製品を指定順で表示する。
2026-10-20の本人訂正により、受託部へGoDD MCPを追加した。
GoDD MCP αとは別製品とし、固定IDとrepository/ownerの対応は
[製品識別の仕様](distinct-godd-mcp-products-3103.md)で管理する。
情報システム部は PCの道具、local-ai-concole、OpenCodex と、以前の指示による内部部署 Skills を表示する。
稼働担当が0でも指定製品を消さず、製品内のジョブは最初は閉じる。
稼働状態で製品の順番を並べ替えず、画面の更新後も利用者が選んだ開閉を保持する。

同じ製品の記録を別名で分裂させない。製品表示の変更は登録名・パス・ジョブIDを書き換えない。
`CC` は PC全体の管理の登録であり、cashcow とは別の記録である。
所属が未指定の登録は6部署の正式一覧へ推定配置せず、一覧の後の別欄に残す。
完了済みだけの登録、担当0件の登録も照合対象とし、以前に決まったSkillsの所属は保つ。

## 保護設定の原本を取得できないとき

原本の復旧成功を推定しない。`protectionMode=masked_metadata` と `sourceOk=false` を保持する。
本人が指定した名前と完全一致の別名だけ表示する。登録パスの末尾が指定製品に完全一致する場合も、元のパスを返さず指定名だけを表示する。
これ以外の名称は以前に本人が使った有限の製品名か、作業番号を含む匿名の登録名になる。
作業本文・自由文・パス・質問と回答・履歴は出さない。表示する作業種別は固定語彙だけであり、元の本文を言い換えて出力しない。
進捗は記録済み0〜100、状態は認識した値、依存は数値ToDo番号、時刻は記録された時刻だけを表示する。
最終成果の時刻と担当の開始時刻を更新時刻から埋めない。

限定表示は `/api/operations` と `/api/agent/display/{todo,jobs,handoff}` に適用する。
後者はコンソールに設定された実際の記録パスを使う。読み取り失敗は503で返し、空の成功にしない。
`metadataOnly=true` と `actionsAvailable=false` で、本文や操作権限が取得できたと誤認しない。
待機の総数と `recovery_unverified` を分け、失われた元記録の確認を単なる起動枠待ちと表示しない。
CPU・メモリ・実行枠は新しい監視記録を取得できたときだけ表示する。原記録の欠落で作業の状態まで消さない。

## コンソールの健康確認

旧10013の健康確認が失敗しても、10012の本体は独立にHTTP200で稼働を返す。
サービスごとの状態は実際の応答を使い、接続できないことを推定オンライン・モデル0件にしない。
未取得は `online=null`。本体の稼働、部分障害、旧サービスの状態を分ける。
各検査には時間と応答サイズの上限を付け、Dockerは名前付きパイプへの読取りだけで確認する。

## 検査と実画面の限界

Rustの検査とNodeのDOM回帰で、指定一覧、別名の統合、匿名化、開閉保持、質問台帳欠落を確認する。
Chromeで `ERR_BLOCKED_BY_CLIENT` が出たときはアプリ画面を確認できたと報告しない。
正規のブラウザ検査を失敗したまま別URL、使い捨てのプロフィール、保護解除で迂回しない。
サーバーの実応答、DOM検査、実画面の観測は区別して報告する。

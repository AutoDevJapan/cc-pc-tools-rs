# Discordの質問投稿と進捗投稿を分ける

2026-10-11のオーナー直接指示を実装する。新しい質問は毎回新しい投稿へ作り、最初の本文でオーナーだけに1回メンションする。`ask --thread` は元の作業の指定であり、そのスレッドへの質問追記ではない。`post`、通知つき`log`、受付・回答再開の具体的な判断結果にも同じ規則を適用する。

質問とは別に新しい進捗投稿を作り、元の作業投稿URLと質問URLを載せる。受領、回答反映の保留、進捗、成果、添付、停止からの復旧結果は進捗投稿へ送る。本文メンションを除去し、`allowed_mentions`は空のparse/usersと`replied_user: false`、メッセージフラグは`SUPPRESS_NOTIFICATIONS | SUPPRESS_EMBEDS`とする。製品・題名・作業フォルダを引き継ぎ、別の仕事を合流させない。

## 保存と回収

- `state.json`のquestionsには元の仕事のjob/session/ToDoと質問・作業・進捗のID/URLを保持する。回答カーソルと受領記録の識別子は元の質問IDのままにする。結果の台帳も元IDを保持し、実送信先を別フィールドに固定する。
- `question-progress/<intent hash>.json`はDiscordへの変更前に作成する。完全な本文、投稿者、元作業、仕事の識別子、添付の指紋から同じ送信意図を決める。必要な添付は同じ記録の隣へ保存し、回収時にサイズとハッシュを再確認する。
- 新投稿のPOST前に送信意図と直前の一覧カーソルを保存する。成功応答や状態保存を失っても、同じbot・題名・本文・添付・カーソルで実投稿を回収する。結果が不明なら再作成しない。明示的に拒否されて未作成と分かる場合だけ同じ意図を再試行する。
- 文章の続きと結果にはnonceと送信前カーソルを保存する。nonceの保持期間が過ぎても、カーソル以後の本文・添付を照合する。初回質問の返信カーソルを後続bot投稿へ移さず、投稿途中のオーナー回答を取りこぼさない。
- 定期処理は新方式で中断した意図だけを1回1件回収する。古い質問を新しい投稿へ移したり一斉メンションしたりしない。新方式の質問に時間経過の再メンションを送らない。

回答は従来の通常配送で元の担当とToDoへ渡す。質問のクローズは回答の反映と未配送の検査を保持する。作業の継続時にも回答済み質問を閉じ、元のToDoと次の担当の追跡を残す。新しい判断はさらに別の質問・進捗投稿を作る。元の作業投稿は完了時にだけ閉じる。

## 検証

`question_progress`と`question_result_routing`の回帰検査は、投稿成功後の保存失敗・通信応答消失・再試行・無通知の受領と結果・元回答カーソル・質問クローズ・旧質問の維持を確認する。既存の質問・添付・受付・回答回収検査も維持する。

`cargo run --locked -p cc-ask --example question_progress_probe -- <所有記録のある空の専用フォルダ>`は、既存の送信先とbot権限だけを使う少数確認である。質問のメンションを送信境界で無効化し、本番の質問状態へ登録しない。元作業・質問相当・進捗の3投稿と進捗1件を読み戻し、メンション0、無通知・プレビュー抑制、再試行の追加投稿0を確認する。成功後は自分が作った3投稿をアーカイブして読み戻す。`probe-started`があるフォルダを再実行しない。失敗時は保存されたIDと新方式の意図から自作投稿だけを回収する。

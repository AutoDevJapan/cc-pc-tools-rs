## 受入条件（先に定義）

1. 16資料に取得日時、固定commit（WebはURL・日時・内容ハッシュ）、実読パス、license、採用/既存統合/参考のみ/未達と理由がある。
2. 独立した新規Skillを実配置し、関連する既存Skillを実改善する。薄い別名を増やさない。新規ディレクトリは作成前に不在を確認する。
3. 変更対象のnameとディレクトリが一致し、日本語descriptionが60字以内。本文は短く、詳細と出典・固定commit・license・適用上の変更は参照へ分離する。ローカル相対リンクが実在する。
4. 各変更に適用正例と負例を定義し、別モデルが未提示の代表依頼で適用と境界を検査する。上位指示との矛盾、実行・費用・権限の拡大がない。
5. 新しいCodex app-serverのskills/list（モデル呼出しなしを優先）で変更対象を発見し、解析エラーとcontext予算警告を確認する。全一覧内容は公開しない。
6. 同じ分類で数と品質の前後、対象のハッシュ、junction維持、別モデルレビュー、関連CIを記録する。文書中心の変更に製品全体ビルドは行わない。

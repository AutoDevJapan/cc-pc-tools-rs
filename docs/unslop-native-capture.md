# Unslopのnative生成と履歴取得

この変更は、出所を確認するcoreに、Windows上の実ファイルと子プロセスを扱う接続を追加する候補です。
実際の正式ビルドとインストールは、レビューと必要なCIを終えてから行います。

## 配布物を生成する

`normalUnslopLiveCaptureAccess` は、固定したUnslopのcommitと10個のGit blobを照合し、新しい専用namespaceへソースを展開します。
Cargo.lockに対応する依存、実際に使う設定、toolchainを保持し、ビルド前後の内容とidentityを比較します。
既存のCargo設定や認証ファイル、旧リリース、保護された評価packetは読みません。

Cargoは既存の共有ゲートと、有限の入出力を所有する子プロセス管理を通して起動します。
PIDと作成時刻、終了コード、Job全体の回収、stdoutとstderrの自然EOFをそれぞれ確認します。
入力は1MiB、出力は8MiBまでです。出力が超過してもパイプは読み続け、結果を不完全として拒否します。
任意のcallbackやReader・Writerを子プロセス実行中に呼びません。

受け取った同じ全出力を検証してから、対象の実行物とCargoの完了結果だけを取り出します。
元出力と投影JSONのハッシュは別に照合します。
元出力は結果に含めず、成功・失敗ともにメモリから消去します。

生成側workerは入力と実行物の二つのCargo aliasを保持したまま、nonce・入力manifest・内容のハッシュとidentityをReadyで通知します。
親は同じ保持バッファを照合し、pendingのexportを作った後に同じnonce・hash・identityを含むACKを返します。
workerはACKを受領したことを明示してから終了し、親が正常終了・EOF・Job全体の回収を確認した後にだけreceiptを確定します。
入力と設定の後片付けが終わった後、exportの保持を継続してidentity・内容を照合し、非上書きのreceiptを発行します。
公開直前の取消は拒否し、公開後にCloseが失敗した場合はreceiptが公開済みであることと後片付け失敗を分けて返します。
このreceiptを読み直すだけで、次回のインストールを許可する入口は設けません。
生成後に確認した実行物・receipt・identityをレビュー済みconsumerへ固定する工程を残します。

## 履歴を取得する

正常なlauncherからapp-serverへ接続し、read-onlyのthread・turn・itemを取得する有限transportを用意します。
新しいthreadの作成、resume、生成turnは要求しません。
取得したmetadataは元のファイルを読む資格ではなく、元の実行と入力・応答を照合する材料です。

現在のstdin batchを送ってEOFにする方式は、実metadataのテストで必要な応答がそろわず失敗しました。
この結果を成功にはしていません。
初期化の応答を受けてから次の要求を送り、要求IDと応答IDが一致した場合だけ進む有限protocolの値とテストは用意していますが、共有実行処理への接続は未完了です。
元のthread・turn・command itemと出所の組が取れない場合は、packetの本文を開きません。

## テストと残作業

固定ソースのテストでは、入出力の上限、JSONとハッシュ、実PID・作成時刻と子の回収、未取得のtool Call IDをnullに保つこと、receiptの衝突・途中失敗、取消、必要なファイルができた後の取消を確認します。
起動前の取消と、子が準備できてからの取消は別のケースです。
Readyの実パーサを通した数値の作成時刻で、同じファイルの正例と作成時刻だけが異なる負例を確認します。
実際の `WithArtifact` からstageとACKへ進む経路を通し、共通のファイル保持処理と呼び出し側の照合をそれぞれ確かめます。
子プロセスの回収は実際の終了状態で判断し、取消・入出力・終了コード・ACKの成否は個別に確認します。
既存の短い起動期限へ依存するテストは、準備完了の合図を待ってから取消する形に直します。

次の項目はテスト成功と別に確認が必要です。

- 共有dispatcherには5つの固定入口と内部workerを接続済み。同じ最終ソースのレビュー・CIと、各入口の実受入を続ける。
- 事前の入力記録から始める一回の正式ビルドと、同じ実行物でのCLI・MCP受入。
- 元のインストール先への反映と起動確認。
- 正常な履歴protocolと元packetの出所の照合、評価側への受渡し、元2例の独立評価。

旧リリースの成功記録と、未取得だった完全な入力記録は分けて保持します。
新しいビルドや履歴metadataで、過去に記録しなかった事実を補完したことにはしません。

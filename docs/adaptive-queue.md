# ジョブの同時実行上限

自動調整はCPUと空き物理メモリを主な材料にする。`adaptive: {}` で有効にし、開始値は `max_running`。初期設定の最小値は4、最大値は60。毎分の `cc_queue_adjust.exe` が独立したロックを取得して測定する。減枠は新規起動だけに適用し、実行中のジョブを終了しない。

## CPUとメモリによる全体の上限

CPUはWindowsのGetSystemTimesの差分で前回からの平均を計算する。メモリはGlobalMemoryStatusExの空き物理メモリを使う。CPU75%未満、空き16GiB以上、プロキシの応答1秒未満で、実行枠を使える順番待ちがあれば増枠する。CPU75〜85%は維持。増加数は通常「2」と「上限の8分の1」の大きい方。CPU60%未満かつ空き24GiB以上なら「4」と「上限の4分の1」、CPU40%未満かつ空き32GiB以上なら「8」と「上限の半分」の大きい方に加速する。最小4から4→12→20→30→45→60と回復できる。

CPU85%以上はCPU80%相当へ下げる（少なくとも10%減）。空き16GiB未満は20%減。応答失敗・連続2回の遅延は半減、単発の遅延は増枠を保留する。CPU・メモリの欠測は現状を維持して次の測定を待つ。利用枠の取得失敗や429の安定待ちは、全体の増枠を妨げない。CPU高負荷の閾値とメモリ閾値は設定可能。

依存の完了待ち、429の再試行時刻待ち、子の上限で待つものは増枠の根拠にしない。古い状態・時計の巻き戻り・壊れた状態は最小値から再測定する。壊れたJSONは原文を残し、I/O失敗を未作成扱いで上書きしない。

## 全アカウントの利用枠とClaudeへの振り分け

OpenCodexのOAuthによる利用枠取得を5分ごとに行う。Codexの全アカウントは `.opencodex/codex-quota-cache.json` の `quotas` からも補完する。更新から360秒を超えたキャッシュは枯渇判定に使わない。CLIが停止・再認証・検証待ちなどで除外したものはキャッシュで復活させない。保存するものはアカウントID、週の使用率と回復日時、短時間枠の枯渇だけ。メール・認証情報・生の応答は保存しない。

同じID・回復期間の5分〜1時間の観測から、各アカウントの使用率の増加を時間で割って合計する。残り使用率を回復までの時間で割った値も全アカウントで合計し、両者の比を週のペースとする。未使用アカウントの回復日時が動いても、その残り枠を含める。期間変更や使用率減少は、そのアカウントの消費比較だけを作り直す。

平均残量が10%を超えていれば、ペースが速くても減枠しない。平均残量10%以下で比が1を超えた場合だけCodex側を全体の4分の1程度に制限してClaudeへ回す。全アカウントの週または短時間枠が尽きた場合はCodex側の新規起動を0にする。全体とClaude側の上限は下げない。

Claude側は起動時16枠を基準にし、PCに余裕があれば全体の上限まで増やす。PCの上限が16未満ならそちらに従う。Claude自身の利用枠が尽きた場合だけClaude側を0にする。429が複数発生した場合は、そのサービス側だけ半減し、5分の安定時間を確認する。同じ429では繰り返し減枠しない。明示モデルや進行中のセッションは変えず、自動選択された新しいジョブだけをClaudeへ振り分ける。

## 固定値の保持と解除

`fixed_max_running` は直ちにその値を起動判定へ適用する。固定中も自動計算を並行して記録するので、切り替え前に実測できる。

設定は `codex_jobs.exe update-queue-config --patch-file <JSON>` で部分更新する。既存の固定値、変更対象外の項目、`adaptive` 内の既存項目を残す。パッチが固定値を省略したりnullにしたりしても解除されない。不正な更新は書き込まず失敗する。設定ファイルを直接上書きしない。

自動上限16以上と健康なCPU・メモリ・応答を連続3回確認し、CPUが目標70〜85%へ近づく履歴も確認してから、`update-queue-config --clear-fixed` で解除する。コマンドは設定の一致・測定の鮮度・3回の確認を検査し、変更履歴へ1行追記する。同じ解除の再実行で重複記録しない。

`queue-limit-state.json` に全体と各サービスの上限を保存する。履歴は最大1440回。`status --json --summary` の `summary.limit` に実際の上限、固定中の自動計算値、CPU、メモリ、応答、ペース比を表示する。起動判定は同じ1つの保存状態から全体と各サービスの上限を読む。

配備は `codex_jobs.exe` と `cc_queue_adjust.exe` の差し替え、`adjust-limit`、`reload-queue` の順に行い、待機中の見張りへ新版を反映する。

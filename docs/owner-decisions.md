# 同じ判断を繰り返し質問しない

題名、説明の言い換え、担当、セッション、結果ジョブが変わっても、新しい判断にはならない。質問投稿と無通知の進捗投稿を分けるルールは、同じ内容を再送する許可ではない。

新しい対象・仕様・危険範囲がある場合だけ、新しい質問を作る。通常の `ask` は次のJSONを `--decision-file` で渡す。結果を受付から送る担当は本文へ `<!-- cc-decision {同じ形式のJSON} -->` を1つ含める。この内部情報はDiscord本文から除去する。

```json
{
  "todo_id": 123,
  "resources": [{"kind": "path", "id": "D:/models/unused-copy"}],
  "decision": "archive-and-delete",
  "scope": {
    "archive": "指定された保管先の識別子",
    "verification": "size-and-sha256",
    "retain": "稼働中のモデル領域は保持",
    "spec_revision": 1
  }
}
```

`todo_id` は担当が変わっても元作業を指す。対象は名前だけでなく実際のパスや資源IDで表す。`decision` は固定の種類 `archive-and-delete / delete / publish / money / rights / customer / direction / irreversible / access` を使い、題名や言い換えを入れない。権限範囲には保管先・保持対象・危険範囲・仕様など実際の条件を書く。再試行で版番号を増やしたり、新しいToDoへ付け替えたりしない。所有者は設定から決まり、別の所有者の回答は使わない。Windowsのパス表記とJSONのオブジェクト順は正規化する。

同じ判断なら、未回答・クローズ済みとも既存URLを返し、投稿・メンションを増やさない。添付の名前・符号化・ハッシュ変更だけでは新しい判断にしない。判断条件を変える添付はその対象やハッシュを `resources` または `scope` に明示する。回答済みなら元の質問本文・添付記録と、現在の本人回答の原文・本人ID・返信ID・日時・元スレッドIDを返す。a/bの意味は元の質問の選択肢で読む。以前の回答スナップショットも履歴として保持する。回答を読むために配送済みカーソルやクローズ状態を変更しない。

旧方式の入力は最初の質問と完全同文の再試行を保持する。言い換えや対象範囲が不明な再質問は `decision_scope_required` と既存URLを返す。本文の類似度から古い承認を新しい対象へ推測適用しない。自動の結果配送はこの状態をエラーとして記録し、質問を送信しない。過去質問の一斉移行・再送はしない。

過去の質問に元ToDoがなく、担当の記録が複数のToDoに残っている場合は、その候補を一意に選ばない。候補がすべて有効な番号で、新しい質問の確定した元ToDoを含まない場合だけ、別の作業として比較から外す。候補が重なる・不明な番号を含む・明示した元番号が担当の記録と矛盾する場合は拒否する。新しい入力自身の所属が曖昧な場合も拒否する。

送信を増やさずに実登録境界を検査する場合は、`cargo run --locked -p cc-ask --example decision_registration_probe -- <所有記録のある新しい検証フォルダ> <保存済みdecision.json> <保存済み質問本文> <元job ID>` を使う。過去の旧方式の質問から比較用の番号とcontextだけを検証フォルダへ写し、実Discordの親チャンネル・bot本人をGETで確認した直後に止める。本番台帳・質問・返信を書き換えず、POSTしない。同じ判断が既に記録されていれば `lookup-decision` を案内する。この検査は送信前の比較とAPI読み取りの確認であり、投稿成功の証明ではない。

確認済みの重複だけを `reconcile-decisions --manifest <JSON>` で結ぶ。形式は `identity`（上のJSON）、`threads`（確認した質問IDの配列、最大10件）、`evidence`（各本文・対象範囲を確認した根拠）。登録済みの完成した質問と、設定されたサーバー・投稿者・元本文の一致を検査し、本人返信を取得して永続保存する。コマンドは投稿・担当起動・返信削除をしない。質問のクローズは別の明示操作で行う。

全経路は `question-progress.lock` で検索から保存・作成まで直列化する。POST前の意図保存と応答消失の回収を保持する。言い換えた再試行も元の本文・題名で回収し、本人回答の取得・保存が失敗したら送信を増やさず失敗を返す。対象操作の自動審査拒否は本人性の問題ではなく、同じ判断を聞き直す根拠にもならない。正確な拒否理由と次の処置を元ToDoへ記録し、拒否された操作を迂回しない。

# 共有ToDo

既存のToDoコマンド、スケジューラー、管理画面から同じタスクを扱うための保存サーバーとPC接続アダプターです。
タスクは認証後にだけ表示します。完了履歴、ID、依存関係、既存の未知のJSON項目と型を保ちます。

## サーバー

```text
go test ./...
go build ./cmd/shared-todo
```

環境変数:

| 変数 | 用途 |
| --- | --- |
| `TODO_DATA_DIR` | 永続ディスク上の保存先（必須） |
| `TODO_ADMIN_TOKEN` | 管理画面のパスワード。32文字以上のランダムな値 |
| `TODO_SYNC_TOKEN` | PC同期専用の別の認証値。32文字以上 |
| `TODO_PUBLIC_URL` | 管理画面のHTTPS origin |
| `PORT` | 待受ポート。省略時8080 |
| `TODO_LISTEN_HOST` | 待受アドレス。PC内テストでは`127.0.0.1`を指定 |
| `TODO_DEPARTMENT_ORDER` | 部署名の表示順を指定するJSON配列。未指定なら配属データから取得 |
| `TODO_ALLOW_LOCAL_HTTP` | `1`のとき、使い捨てのPC内テストでHTTPを使う |

同じデータディスクを複数のサーバープロセスで共有せず、レプリカ数は1にします。
DockerfileとRailway設定を同梱しています。`/data`を永続ディスクへマウントしてから配備してください。
`/healthz`は保存先が利用可能なときだけ200を返します。
認証値、データ、移行ファイルをソース管理へ含めないでください。
登録済みのPCからブラウザーへ接続する場合は、`/connect`に表示された接続番号を、管理者認証付きの`POST /api/v1/connect/{id}/approve`で確認します。
その後、同じブラウザーで「接続を確認」を押します。番号だけではログインできず、ブラウザー固有の秘密と管理者による確認の両方が必要です。

## PC接続と移行

`todo-cloud-migrate export`で既存のバイトロックを使って原本と参照資産を取得し、`upload`で送信し、`verify`で転送結果を照合します。
存在しない参照先を空ファイルで埋めず、未取得の状態と元の参照を保持します。
初回の取り込みは空の台帳に限り、転送済みの処理を再送しても重複しません。

`todo-cloud-bridge configure --config <path>`は標準入力の接続設定をWindowsユーザー単位のDPAPIで保護します。
設定には`baseURL`、`syncToken`、`clientId`、`cachePath`を指定します。
認証値をコマンドの引数へ含めません。
すべての読み書きプログラムを更新してから`cutover --config <path> --bridge <absolute-path>`で最後のPC上の差分を反映し、接続を有効にします。
切替後の`todo.json`はキャッシュです。サーバーへの書き込みが失敗した際にPCだけへ保存する動作は行いません。
切替では初回取り込みの版（通常1）を照合し、その後にWebで変更があった場合は上書きせず照合へ戻します。
結果が不確定だった切替を再実行する場合は、保存結果を確認してから`--expected-cloud-revision`でその版を指定します。

PCの1バイトロックとサーバーの期限付きリースで、既存のCLIトランザクションを保ちます。
管理画面の保存は表示時の版を確認し、別の更新が入った場合は409、PCが更新中の場合は423を返します。
同一操作IDの再送は保存済みの結果を返します。
部署と担当Agentの台帳はタスク原本と別に保存し、実行中、配属済、未照合、完了履歴を区別します。

## テスト

```text
go test -race -timeout 120s ./...
go vet ./...
```

架空データで、同時更新、期限切れ、結果不明時の再送、認証、CSRF、検索、移行中の破損検出、原本の未知項目の保持を確認します。
PCへの有効化と本番データの転送は通常のテストでは行いません。

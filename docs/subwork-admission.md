# レビュー受付後の予約解除（ToDo2416）

有限な下位作業の受付は、スケジューラーが資源・容量・所有範囲を確認してから保存する。準備で作った起動キーだけでは受付済みとは扱わない。

起動前は保存した受付と現在の予約キーを照合する。同じ起動キーの登録済みジョブがあれば、別の担当はその予約を使えない。正規の担当登録で予約が解除された後は、同じ起動キーを持つ実ジョブへの移管を確認する。ToDoの担当履歴・現在の担当・受領した担当と世代・実行段階が一致する場合だけ、予約解除を認める。別の予約が作られた場合は過去の担当記録で許可しない。

両方の状態で、保存した受付の起動キー・仕様・必要資源・親の由来・作業フォルダーを現在のToDoと実ジョブに照合する。実際のリポジトリ・Git共通ディレクトリ・独立したworktreeとブランチ、親子の循環、PRの所属、本人判断待ち、未完了の依存も再確認する。担当登録は実行開始とは異なり、実行枠や所有範囲の通常検査を免除しない。

回帰検査は正規の有限作業受付から、ジョブ登録に伴うToDoのStart処理、予約解除後の起動検査、同じ受付の再照合までを通す。同じ受付で二重起動しないことと、条件変更を拒否する対照を維持する。

配布後は既存の`reload-queue`で待機中の監督へ更新を反映する。新しい受付は作らず、同じ担当の開始時刻・セッション・モデル・読み取り権限と固定差分の確認結果を元のToDoに記録する。OmegaPortalの元ToDo1460/1167の全受入を、この有限な修復の完了へ縮めない。

# モデル混雑時の既存OAuth枠への切替

`Selected model is at capacity` は正規の `error` / `turn.failed` イベントからのみ検出する。引用、ページ、ツール結果、標準エラーの文字列検索では切り替えない。認証、取り消し、クォータ、一般の要求失敗を区別し、具体的な混雑エラーの後の一般的な終端エラーでも証拠を保持する。

元のjob、ToDo、セッション、作業場所、指示、権限、差分、子担当、依存待ちを保存したまま、OpenCodexの既存OAuthクォータを確認して別providerを優先する。ChatGPT枠の種別は `codex`、Claude枠は `oauth`。APIキーの種別は除外する。新しい認証、scope、契約、クレジットの操作はない。

切替は保存された履歴で同じ候補の再試行を避け、最大3回。条件を満たす枠がなければ同じjobをqueuedにして15分後にクォータを再確認する。待機は最大3回で、その後は技術的な終端失敗にする。スケジューラーは待機中のjobを取り消さず、終端失敗の予算を新しいjobでリセットしない。本人への質問やblockは作らない。終了確認がAccessDeniedになる、PIDの作成時刻が不明、元の子がまだ生存する場合は重複再開しない。

レビューはtask_typeとレビュー用の名前から識別する。元実装担当のmodel、requested_model、切替履歴を除外する。親の来歴または明示された除外モデルが確認できなければ切り替えない。Haiku指定のsingle_file_*作業は元の単一fileの指示と役割を保ち、代替も軽いモデルのgpt-6-lunaに限定する。レビューを実装用モデルへ広げない。

`cargo run --locked -p cc-jobs --example capacity_oauth_acceptance -- <受入記録先>` は明示実行専用。既存OAuthで最初の応答を取得し、正規形の混雑イベントを検査で注入して、同じセッションの別providerによる実応答を確認する。自然発生した混雑の実測とは区別する。通常のテストはCLIのクォータをfixtureに置き換え、AIを呼ばない。

## 完了確認（2026-10-15）

この機能は親の[PR144](https://github.com/AutoDevJapan/cc-pc-tools-rs/pull/144)へ統合され、固定した変更のCIと別モデルの確認後、mainへマージされた。子のPR153は重複するため終了済みで、古い差分を再マージしていない。

- 固定ソース `b9201e3a8bfd52bf90e17e2ae7a788aafcdabf48` の必要8ワークフローが成功。全件2164件、doctest、全ターゲットClippy、CodeQLを含む。[Build speedの結果](https://github.com/AutoDevJapan/cc-pc-tools-rs/actions/runs/38494168170)
- 親担当が配置した実行ファイルのハッシュと現在のジョブ管理プログラムが一致した。スケジューラは後続PR177の版へ更新され、後続の配布記録と現在のハッシュが一致した。どちらにも今回の切替処理が保持されている。
- 配布後の再受入で、既存OAuthによるOpenAIの実応答、正規形の混雑エラーの注入、Claudeの実応答を確認した。同じセッションと元ToDoを保持し、切替回数は1回だった。自然に発生した混雑の観測とは区別する。
- 再受入に使った検査用実行ファイルと稼働版について、切替・イベント・クォータ判定のソースが一致した。稼働版そのものへのエラー注入は行っていない。既存の固定ソースの回帰検査と配布ハッシュの照合を合わせて受入とした。

古い実行ファイルの再配布、既存担当の一斉停止、認証変更、追加課金は行わなかった。今回作成した受入用の一時領域は、所有記録に従って削除し終了を記録した。詳細な実測と版・ハッシュは指定された作業記録の `result.json` に保持する。

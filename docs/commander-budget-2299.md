# 巡回予算による持ち越しと候補の実失敗

PR #100後の追加修復。受信後の残り時間で起動確認が中断された候補に、失敗回数と1時間の待機を課していた。

- コマンド自身の上限に達した場合は `command_timeout`、巡回の残り時間が上限を短くした場合は `patrol_deferred` とする。後者では候補の失敗回数や待機期限を増やさず、元の候補を末尾へ回して保存する。親の期限が尽きた準備確認も同じ扱いにする。
- 過去の範囲未分類の時間切れは元の回数・時刻・待機期限を監査記録へ残し、一度再確認する。新しいコマンド自身の時間切れは `timeout_scope: command` を保存し、実失敗の待機を維持する。
- 常駐巡回だけ、保存済み受付の起動確認をPR取得と受信より前に行う。起動確認を始めるには20秒以上の残り時間を確保する。受信後の少ない残り時間で二度目の起動処理はしない。巡回全体の上限は延長しない。
- 待機する候補は2件の実準備枠を消費しない。共有ToDoに対応する候補と単独の引き継ぎを交互に先に確認する。巡回の順番を保存し、同じ種類だけが新しい時間枠を占めないようにする。
- 元の本文・受付キー・source・モデル・effort・sandbox・aliasを保持する。再受付や直接の別root起動は行わない。起動直前の最新所有確認と、起動済み受領の回収を維持する。

受入は原2301と2236の実開始、またはモデル利用枠など具体的な外部待機の確認まで。受付保存・queued・巡回期限の繰り返しだけでは合格としない。実測と新差分の検査結果は同じ2299の記録へ保存する。

追加受入では、旧未分類の時間切れを容量確認より前に受領・所有・除外の記録だけで照合する。明示番号がない旧元ジョブも、既存の一意なToDo関連判定と保存済みのリンクが一致する場合だけ再確認へ戻す。新しい実コマンド時間切れ、未解決の所有、完了・回答待ち・依存待ちは解除しない。

API受付は通常のcheckout判定を保ち、元担当を明示した同受領の非Git作業場所に限り、実起動の `receipt_artifact_directory` を再利用する。元ジョブの関連ToDo配列も読込時に保持する。独立作業の範囲、元の本文・キー・モデル・権限を変更しない。

検査: PCのConsole278件成功・2件skip、GitHub側253件成功・2件skip、doctest・Clippy・release成功。最後の旧受領の補強は両環境の関連10件とClippyで確認。HTTP検査は同受領と関連受領の受付から起動まで、同cwd・元source・ToDo番号・read-onlyの保持を確認した。foreign・ancestor・関連なし・別ToDo・元sourceなし・型不正・受領なし・除外・done・block・waitの11負例は拒否した。

追加レビュー `20261011-025737-review-commander-intake-2299` はMust0。最後の旧受領照合は `20261011-030614-review-commander-metadata-final-2299` で確認する。旧PR100の成功済み全検査・投稿・委任は繰り返していない。配布後の原受付と実開始の証拠は同じ2299の永続検証記録へ保存する。
起動を保留した分岐を `last_wait` へ記録する。待機の記録は失敗回数・待機期限・受領本文・指定・別名を変えず、通常の保存時に反映する。同じ候補の容量確認から得た数値と一般的な理由だけを使い、別案件のジョブ別計測は保存しない。対象IDなし・別対象・古い観測は詳細を再利用しない。診断の保存失敗で起動の許可判断は変えない。

追加検査では、元会話を使う別担当がいるときの保留理由と受領・監査の保持、および同じ対象の新しい容量観測の正例と6負例を確認した。元2301・2236・1021・1178の実開始は既に同じ2299へ保存済み。1241の保留条件をこの記録で確定する。
共有の起動ロックを取得できず候補確認の前に戻る場合も、巡回全体の待機として記録する。ロック解放後に同じ受領が起動できる回帰を確認した。

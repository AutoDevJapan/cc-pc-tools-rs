# 製品の表示名をRe:Xへ統一する

`todo.exe rename-project <旧表示名> Re:X [--replace-name <別の表記>] [--dry-run]`
は共有ToDoのロックを取得してから最新の保存内容を読み、指定したプロジェクトのキー、所属項目の製品名、タイトル、note、notes、および停滞記録のキーを更新する。
別のプロジェクトは変更しない。改名先が既に登録されている場合や対象の表示欄が文字列でない場合は、保存せずエラーにする。
改名済みのデータに再実行できる。出力は保存が成功してから返し、件数にはプロジェクト、所属項目、本文を変更した項目、本文の欄を分けて記載する。
`--dry-run`は同じロックと検証を使い、保存しない。

状態、担当ジョブ、進み具合、依存待ち、起動指示、スケジューラーの記録、未知の欄は保持する。
実際に変更する改名ではロック内で直前状態のバックアップを作成する。同じ内容の再実行ではバックアップを増やさない。
URL、PCパス、API識別子の中の表記は互換性のため保持し、文章中の製品名だけを置換する。
GitHubの識別名はRe-X、製品の表示名はRe:Xである。
親ToDo2053でリポジトリの改名済みURLへ移す場合は、`--github-from <owner/旧slug> --github-to AutoDevJapan/Re-X`を併用する。
この指定は対象プロジェクトの本文にあるGitHubのWeb URLだけを更新する。API URL、別リポジトリ、既存PCパスは保持する。

`codex_jobs.exe rename-project <ジョブID> --from <旧表示名> --to Re:X`
はそのジョブのstate.lockを取得し、project、name、task_titleの表示だけを更新する。
稼働中の旧実行ファイルは開始時の表示名を再保存する場合があるため、同じフォルダのdisplay-name.jsonに改名規則も保存する。
稼働中の旧担当は進捗の書込でロックを取らないため、改名CLIは稼働中のjob.jsonを上書きしない。
更新済みのCLIは読取時と保存時にこの規則を適用する。古い担当がjob.jsonを上書きしても、最新の進捗や実行状態を保ったままRe:Xとして読める。
旧実行ファイルを使う担当が終了するまで、job.json単体の生データには旧表示名が再出現する場合がある。
cwd、ID、起動キー、プロセス、実行内容は変更しない。
改名規則が壊れても、ジョブ一覧や実行状態の保存は保持し、診断を残す。
作業の重複判定は旧表示名とRe:Xを同一とみなし、改名前後で担当の判定が分かれないようにする。

cc-task-titleは旧パスやGitHubの識別名から推定する製品名をRe:Xへ変換する。
明示された製品名、項目名、作業名、既存のタイトルキャッシュから表示名を再生成するときにも同じ正規化を適用する。
新規のToDo登録とジョブ登録も同じ正規化を使い、旧名で渡された登録でもRe:Xを保存する。

検証は既存項目の全体比較、別プロジェクトの保持、改名先の衝突、検証失敗時の未保存、再実行、ロック待ち中の更新、旧担当の古い保存内容の再書込、パスとURLとAPI識別子の保持を対象にする。

# 共有ToDoの過去メモを保管する

`todo archive-history <番号>` は変更なしの確認、`--apply` で選択した項目の
`note_history` だけを保管する。現在のメモ・指示・状態・担当・依存・停止は変えない。
共有ToDoの通常ロックと原子的な保存を使い、64MiBの上限は維持する。
元2626の明示的な保管工程はその項目だけが対象だった。
ToDo3651では通常writerにも同じ保管契約を適用する。整形後の書込みが64MiBを超える
場合だけ、大きな旧note_historyから保管し、現在のメモ・指示・状態・担当・依存・
本人回答IDなどは変更しない。1/16（4MiB）の空きを目標にする。履歴の参照が増えて
かえって大きくなる保管は行わず、履歴をすべて保管しても収まらなければ失敗を返す。
計画が上限内に収まることを確認してからファイルを公開する。

履歴はToDo管理領域の`note-history-v1/<番号>-<SHA256>.json`に上書きせず保存する。
原文、日時、未知フィールド、配列順、重複を保持する。Windowsでは元のToDoファイルの
アクセス制御を複写し、Unixでは管理ディレクトリ700・ファイル600を使う。
公開リポジトリやDiscordへ原文を添付しない。

原ファイルの保存と別読み取りでのSHA・内容一致の確認が終わってから、共有ToDoへ
参照と件数を保存する。途中で止まっても元の履歴が残り、再実行は同じ保管済み内容を照合する。
参照のない保管ファイルが残っただけでは、元の作業を完了や反映済みにしない。

`todo history <番号> --offset 0 --limit 20` は必要な履歴だけを原順で読む。
`todo restore-history <番号>` は復元の確認、`--apply` は通常上限内で元の配列へ戻す。
復元時も保管ファイルを消さない。壊れた・欠けた・別項目の履歴を空とみなさずエラーにする。
明示的な復元は自動保管を経由せず、完全に上限内へ戻せた場合だけ保存する。
容量上限によって復元できないときも、historyで原文をページごとに読み出せる。
ToDoの本文・履歴には私的な内容があり得るため、会話へ全文を表示しない。

Operationsの一覧は履歴本文を開かず件数だけを表示する。既存の明細取得は、対象を
確認した後にその項目の履歴を読む。名前の保護や不明な原設定を解除しない。

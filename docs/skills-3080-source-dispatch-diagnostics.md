# 用途を限定した起動処理の診断

`--start-skills3080-runtime-source` は、通常のスケジューラが対象の実ジョブを起動した場合だけ成功を返す。
準備した記録や起動待ちの状態を、入力の記録や利用の成功として扱わない。

従来は、下位コマンドの異常終了、タイムアウト、通常の起動待ちがすべて
`source_normal_dispatch` にまとめられていた。
この段階を維持したうえで、`normal_dispatch` に次の診断を追加する。

- 実プロセスの始動失敗、異常終了、タイムアウト、出力上限、終了後のパイプ待ち。
- 通常スケジューラの固定エラー名と、既存実行・優先順位・実行可能数・準備失敗による未起動。
- 読み取った標準出力と標準エラーのバイト数・SHA-256、取得できた終了コード。

出力は両方を読み、保持する先頭部分は標準出力1MiB、標準エラー64KiBに制限する。
打ち切りのあった実行で、観測した出力が全出力であるとは主張しない。
標準エラーの本文、パス、任意の文字列は返さない。
固定の型と値に合わない診断もCLIの拒否応答へ通さない。
停止、依存、優先順位、資源、通常の担当確認は引き続きスケジューラが判定する。

独立したWindowsプロセスを使う合成テストで、担当確認用の読み取りを閉じた後も、
固定入力の書き込み拒否を維持しながらメタデータの置換・追記記録・新規記録作成ができることを確認する。
このテストを実機で起きた失敗原因の確定とは扱わず、下位診断と実起動で別に確認する。

通常配布済みのソフトは、後継生成前に[同じバッファで観測した記録](evidence/skills-3080-guard-before-source-dispatch.json)へ固定する。
その版が正常に発行した準備は、元の呼び出し・要求・nonce・物理ID・担当・時間窓を保ったまま後継で開始できる。
これは観測済みの完全なソフト識別子の組だけを認める移行であり、不明な版や、同じhashだけを自己申告した入力は認めない。
開始に使う現行ソフトのマージ確認も維持する。

実機での起動、入力の記録、正式レビューの受領、新規配置、実行中と終了後の利用、
同じバッファによる発見・適用は、それぞれ実結果を確認するまで未完了とする。

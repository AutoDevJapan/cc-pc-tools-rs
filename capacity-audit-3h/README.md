# capacity-audit-3h

This Go tool uses the existing `CC-CapacityAudit-3h` task. It **does not delete files**. The owner's 2026-10-24 instruction changes its real interval to six hours while preserving the historical task name. Elevated S4U logon, `StartWhenAvailable`, `IgnoreNew` and the five-minute execution limit remain.

Every run discovers Windows volumes, logical drive letters, disks and partitions using bounded, hidden OS queries. EFI, reserved and recovery partitions are retained, including those without a drive letter. Device labels, serial numbers, mount-directory names and provider exception text are excluded. Missing capacity and discovery errors remain unknown; a previously observed device missing from a successful census is disconnected. A discovery error does not prove disconnection. Capacity deltas require consecutive available measurements of the same hashed volume identity.

An independent `all-drive-state-v1.json` preserves metadata cursors for the discovered drive letters; `all-drive-latest-v1.json` contains only anonymous device and scan results. This does not read or reinterpret an old cleanup ledger. The rotating first drive receives a turn before growth-prioritized drives. Each drive has a ten-second/20,000-entry processing budget within a 45-second all-drive budget. Directories and files require the real guard; unknown/private roots are not enumerated. Transient guard failures retain the exact cursor, separately from protection classification. Reparse points are skipped. A metadata traversal is an observation over time, not a filesystem snapshot or a deletion/unused-data classification. Directory listing itself uses Go's sorted `ReadDir` and may exceed the processing budget on a single very large or stalled directory; the Windows task's finite upper limit remains the outer bound.

`--inventory` returns a fresh device-only census without scanning directories, creating state, queueing a worker or deleting anything. `--all-drives-status` returns only the new anonymous sidecar, never the old raw scan state/log. A missing sidecar fails rather than returning an empty survey. The existing ToDo measurement projection still includes its original seven categories; the finite worker reads the new sidecar separately. Seven-way content classification, source/usage verification, individual deletion, batched questions and permanent decision application remain work for the existing assigned workers, not claims made by this read-only inventory.

The legacy categories measure actual C/D volume free and used bytes and the change since the previous run. E's free space also reports its required 500 GiB margin. The new all-drive traversal may read E metadata only after the same real guard check; it has no deletion authority and preserves existing owner data. The tool also measures the logical file lengths of the known pagefile, hibernation file, swapfile and Docker virtual disk without opening their contents.

Fallback local-volume discovery uses Win32_Volume DeviceID, the same GUID identity as Get-Volume, rather than inventing a second identity from a drive letter. Mapped network drives use a hashed provider identity. A missing network identity is explicitly unknown, with no inferred capacity baseline. Disk/partition sizes can be null. Deadline exhaustion preserves a partial cursor rather than claiming a guard outage. Depth-first cursors and a small invocation-local listing cache avoid accumulating an entire wide parent in the checkpoint. Writes enforce the same 8 MiB ceiling as reads. Corrupt or oversized all-drive state is retained; a fresh anonymous failure result is published and the independent legacy measurement and queue continue. The task still exits nonzero after persisting those independent results, so a detailed-survey failure is visible.

Bounded metadata scans cover the known Windows/application directories. Owner data, machine data, operations and deletion-request trees require a verified negative result from the real client-resource guard. When the original protection settings are unavailable, these categories are recorded as `protected_unclassified`, not as zero size. No private path, file name, task text or raw error goes to stdout or the aggregate run log.

Each legacy category has a 25-second / 150,000-entry budget and total measurement has a 165-second budget. A checkpoint preserves partial directory traversal between runs; the starting category rotates. The legacy checkpoint cannot expand its compiled roots. Reparse points and paths with linked ancestors are skipped. An unavailable path, read error, partial scan, completed metadata scan and whole-drive scan are distinct: `whole_drive_scan` is always false. Reported category sizes are logical lengths, not disk allocation, and may include Windows hard links. A completed metadata traversal is not an atomic filesystem snapshot.

After persisting measurements, the existing task gives its newly generated anonymous report and compiled finite instruction to the canonical `todo capacity-cycle` command, with a separate 45-second deadline. The ToDo lock admits one reusable decision row; the ordinary scheduler alone launches it. Another measurement retains any unfinished, stopped or waiting worker. A new cycle after completion archives its result and dispatch history and starts a fresh dispatch in the same workspace. It never resumes a completed cycle's conversation or inherits its retry counters. No additional Windows task, monitor or direct AI launcher is created.

`todo capacity-status` reads only this connection's anonymous active/latest measurement and result, without opening old scan logs or checkpoints. A missing decision result is null. The worker records investigated resources, uninvestigated categories, candidates, retention reasons, actual reclamation and question creation/sending/answer application separately. Unknown reclamation and verification counts remain null. `capacity-result` binds the result to the exact active generation; the normal `done` command rejects a missing result. Internal immutable cycle receipts preserve prior dispatch references; the anonymous status response excludes that history. Shared-row summaries retain sixteen completed cycles. Queue failure is recorded separately and makes the task fail while retaining the measurements for a normal retry.

The runtime stores a checkpoint in `D:\CC\Tools\capacity-audit-3h\state.json` and aggregate receipts in `runs.jsonl`. The OS lock prevents concurrent checkpoint updates. Corrupt/empty state fails closed; the tool never treats it as a recovered original registry. State and log symlinks are rejected, and checkpoints are replaced through a synced temporary file.


Tests cover boundaries, resumed traversal without duplicate counts, expired budgets, category rotation, checkpoint corruption, an outside-root checkpoint, a real Windows junction and the OS single-flight lock. The parent's Rust workspace test does not include this separate Go module; its Go checks above must be retained in the integrated validation record.

Set `CAPACITY_TODO_TEST_EXE` to the newly built ToDo executable to include the isolated cross-tool CLI acceptance. It verifies one normally dispatchable row, duplicate-input convergence and readback without rewriting scheduling state. Deployment requires a clean tracked source at the reviewed merged commit, committed build evidence and exact old/new fingerprints. Its two software-update qualifications belong to the shared guard owner (ToDo3082); this module does not update the guard or widen protected data access.

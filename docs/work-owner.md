# 同じPRの担当を1つにする

親ジョブは、同じリポジトリのPR番号、Gitの作業フォルダ、または同じリポジトリのブランチが一致すれば、先に登録された担当の完了を待つ。PR番号だけでは別リポジトリと結び付けない。子レビューは `parent_job_id` で親を明示し、この担当判定の対象外とする。

ブランチ一致にはmain等も含む。これは「同じブランチ・同じworktreeで親を重ねない」という依頼をそのまま適用するもの。同じGit作業フォルダの例外も設けない。独立の並行実装には別の作業ブランチとworktreeを使う。Gitではない共有ツールフォルダはworktreeと扱わない。

`cc-job-policy::work_owner` を起動受付、実行枠の取得、ToDoの停滞復旧、Shepherdが共有する。登録と実行開始は既存のジョブ受付ロックで直列化する。起動優先順位が高くても先の担当を追い越さない。担当待ちのジョブが先の最低順位ジョブを足止めすることも避ける。

起動時の `--pr-url https://github.com/<owner>/<repo>/pull/<番号>` を最優先し、Shepherdは必ず渡す。他の受付は構造化した作業名のPR番号と、作業先のGit情報を使う。古いジョブもToDoの作業名で補完する。プロンプトにある過去のPR一覧や共有指示を対象とは扱わない。Git metadataだけを読み、外部コマンドや通信を実行しない。

同じPRの待ち先が共有ToDoを持つ場合、実行枠の取得で待ち先を記録し、次の停滞確認で通常の `wait_on` にする。担当の短いジョブが終了しても、親ToDoがdoneになるまでは自動で再開しない。循環待ちと本人の判断待ちは既存の規則で保護する。待ち先を持たないジョブは、そのジョブの終了後に通常の実行枠で再開する。取り消し中の実行担当は、実際に終了するまで担当として数える。

稼働中の重複担当はこの変更だけで強制終了しない。成果を保存した後に既存のcancelで止め、元のToDoへ受領記録を残す。PR86では880を主担当として採用し、1595・1633・1665・1690・1720・1466を880の完了待ちにした。未検証の成果の保存を、製品の受入条件達成と数えない。

検査は、同じPRの別ToDoと別worktree、並行した枠取得、子レビュー、順位逆転、Gitのサブフォルダとlinked worktree、担当のジョブ終了をまたぐToDo待機、Shepherdのfetch前判定、ToDoの復旧を対象にする。

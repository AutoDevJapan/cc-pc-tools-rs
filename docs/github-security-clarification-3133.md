# GitHubの既存費用質問に説明を補う（ToDo3133）

## 対象と完了条件

元ToDo2945で本人が質問の意味を尋ねたため、既存の質問スレッドへ背景を補う。
親ToDo3110の返信監査や、元ToDo2945の費用判断全体を完了にはしない。
契約・保護設定・請求・公開範囲を変更せず、新しい質問や選択肢、メンションを送らない。
請求画面は表示を読むだけとし、保存や設定変更の操作をしない。

完了には、次の結果をすべて確認する。

1. 元の質問、本人の説明要求、既存の補足を正規のDiscord APIで照合する。
2. オーナーのChromeと既存OAuthの読み取りで、対象の組織・非公開保管庫と費用表示を確認する。
3. 質問の目的、有料保護の内容、無料機能との違い、今後の費用、停止の影響を、同じ質問スレッドへの返信1通に揃える。`discord_ask.exe post`系統の正式な説明補足入口を使い、`ask`で新しい質問を作らない。元の質問と本人返信は編集・削除しない。
4. 正規のDiscord APIで投稿先・投稿者・実メッセージID・本文とメンションがないことを読み戻す。送信結果が不明なら、既存の投稿と固定要求を先に照合し、確認前に再送しない。未確認の送信を完了と扱わない。
5. 元ToDoの問い、本人返信、補足ID、未確定の選択を、既存メモを保持した履歴付き編集で記録する。

通常入口が元質問への説明補足に未対応なら、原因と未送信の事実を保持する。
別経路で送らず、正式な修復と配備後に同じ固定本文・元質問の要求を再開する。
検査専任の担当が原因を確認しただけでは、修復や配備を完了と扱わない。

## 説明で区別すること

- 質問の目的は、保護にかかる今後の費用の継続・停止を本人が判断できるようにすること。過去の請求を承認済みとする質問ではない。
- Code Securityはコードの脆弱性等を検査し、Secret Protectionは秘密情報の混入を検出・防止する。
- ライセンス数は保管庫の件数ではなく、保護対象へ過去90日以内に変更を送った人が基準となる。同じ人が両製品で数えられることもある。
- Dependabotの基本的な警告・更新等は有料製品の購入を必要としない。公開保管庫ではコードスキャン、秘密情報のスキャン・送信防止、依存関係のレビューにも無料で利用できる機能がある。GitHub Actionsで検査を実行する料金は別に扱う。無料対象の根拠は末尾のGitHub公式機能説明で確認する。
- 画面の月額見込と税等を含む確定請求を区別する。以前の表示だけを現在の金額として書かない。
- 非公開保管庫で有料機能を止めると、その機能による検査や秘密情報の送信防止を失う。コードや変更履歴の削除、基本プランの変更とは区別する。すでに発生した料金の取り消しを約束しない。
- 「どういう意味？」という返信から、停止・継続や追加費用の承認を推定しない。

## 検証と再開記録

この変更は手順の文書だけなので、内容・一次資料のリンク・差分を確認する。
GPU、Cargo、製品全体のビルドは必要ない。公開前に別モデルでこの文書を確認する。
実際の費用、非公開対象の一覧、Discordの原文・API取得記録はGitへ追加しない。
送信結果、残作業、作業ブランチとHEADは、作業フォルダの私的な記録と元ToDoへ保存する。
今回の依頼は通常の完了通知を求めていないため、結果の通知を新たに送らない。
作業状況の共有が必要な場合は、元質問へのリンクを添えて既存のメンションなし進捗投稿を使う。
質問側には説明だけを揃え、進捗や別の判断を追記しない。
ブラウザの工程が終わった時点で、所有記録を照合して自分のタブだけを個別に閉じる。

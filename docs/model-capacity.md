# モデル混雑時の既存OAuth枠への切替

`Selected model is at capacity` は正規の `error` / `turn.failed` イベントからのみ検出する。引用、ページ、ツール結果、標準エラーの文字列検索では切り替えない。認証、取り消し、クォータ、一般の要求失敗を区別し、具体的な混雑エラーの後の一般的な終端エラーでも証拠を保持する。

2026-10-20の本人指示により、最初は同じGPTモデルを保ち、異なる適格な既存OAuth枠を最大3回追加で試す。
元のjob、ToDo、セッション、作業場所、指示、権限、差分、子担当、依存待ちを保存する。
ChatGPT枠の種別は `codex`、Claude枠は `oauth`。APIキーの種別は除外する。
新しい認証、scope、契約、クレジットの操作はない。

要求ごとの公開account namespaceを使い、全体のactive accountとpicker設定を変更しない。
失敗した枠は正規CLIのconversation/model限定の要求メタデータから確認し、使用済みの枠を除く。
追加試行は5、15、30秒後。回数、公開識別子、期限を保存し、再起動してもリセットしない。
帰属を確認できない場合や代替providerの利用枠が不明な場合は、同じjobで15分後に再確認する。
技術的な待機は最大3回。適格な別枠が無くなった場合や同モデルの上限後にClaudeを検討する。
複雑な修正・原因分析・重要レビューはOpus5.5、狭い明確な修正はSonnet5.5を先に選び、双方maxを要求する。
モデル切替も最大3回で候補を繰り返さない。スケジューラーは終端失敗の予算を新しいjobでリセットしない。
本人への質問やblockは作らない。元childの排出とPID作成時刻、job/queue/ToDoの所有と世代を照合する。

レビューはtask_typeとレビュー用の名前から識別する。元実装担当のmodel、requested_model、切替履歴を除外する。親の来歴または明示された除外モデルが確認できなければ切り替えない。Haiku指定のsingle_file_*作業は元の単一fileの指示と役割を保ち、代替も軽いモデルのgpt-6-lunaに限定する。レビューを実装用モデルへ広げない。

`capacity_oauth_acceptance`のexampleは明示的な受入用で、通常検査からAIを呼ばない。
既存OAuthで最初の応答を取り、正規形の混雑イベントを検査で注入して、同じモデル・同じセッションの別枠を確認する。
自然発生した混雑の実測とは区別する。担当の直接起動を禁止する実行枠ではexampleを実行しない。
今回の実行済み検査と未確認事項は[ToDo3081の仕様と記録](model-effort-pool-retry-3081.md)へ記載する。

# GitHubの既存費用質問に説明を補う（ToDo3133）

## 対象と完了条件

元ToDo2945で本人が質問の意味を尋ねたため、既存の質問スレッドへ背景を補う。
親ToDo3110の返信監査や、元ToDo2945の費用判断全体を完了にはしない。
契約・保護設定・請求・公開範囲を変更せず、新しい質問や選択肢、メンションを送らない。

完了には、次の結果をすべて確認する。

1. 元の質問、本人の説明要求、既存の補足を正規のDiscord APIで照合する。
2. オーナーのChromeと既存OAuthの読み取りで、現在の対象と費用表示を確認する。
3. 質問の目的、有料保護の内容、無料機能との違い、今後の費用、停止の影響を、同じ質問スレッドへ通常の送信CLIで補足する。
4. 投稿先・投稿者・実メッセージID・本文をAPIで読み戻す。未確認の送信を完了と扱わない。
5. 元ToDoの問い、本人返信、補足ID、未確定の選択を、既存メモを保持した履歴付き編集で記録する。

## 説明で区別すること

- Code Securityはコードの脆弱性等を検査し、Secret Protectionは秘密情報の混入を検出・防止する。
- ライセンス数は保管庫の件数ではなく、保護対象へ過去90日以内に変更を送った利用者が基準となる。同じ利用者が両製品で数えられることもある。
- Dependabotの基本的な警告・更新等は有料製品の購入を必要としない。公開保管庫では一部の高度な保護も無料で利用できる。実行基盤の料金は別に扱う。
- 画面の月額見込と税等を含む確定請求を区別する。以前の表示だけを現在の金額として書かない。
- 非公開保管庫で有料機能を止めると、その機能による検査や秘密情報の送信防止を失う。コードや変更履歴の削除、基本プランの変更とは区別する。既発生料金の取り消しを約束しない。
- 「どういう意味？」という返信から、停止・継続や追加費用の承認を推定しない。

# 現在の本人依頼と元の作業を照合して再開する

元3638の現在の再開依頼を、1626、3277、3549、3623の元の登録へ結ぶ有限の修復。
原保護名簿の復旧、期限切れ証拠の延長、本人停止や依存の解除とは分ける。
PR443の起動登録復帰と通常のdispatcherを利用し、別の起動経路は作らない。

本人の原発言は、元のnativeセッションのユーザー発言で確認する。親の引用や
担当への起動仕様を、本人が直接入力した発言やDiscord APIの回答とは扱わない。
元セッションの識別情報、原発言の位置、原バイトのSHA256、日時とroleを照合する。
その発言が具体化された元3638と実装3650の保存仕様も別々に照合する。
原会話と私的な作業本文を公開リポジトリへ保存しない。

各対象は登録project/root、元仕様の原バイト、実所有者、元担当との対応を確認する。
元1626では既存の元依頼・元担当・作業場所の照合を再利用するが、旧APIは引き続き
期限切れを返す。新しい出所の確認を旧証拠の時刻変更で代用しない。
3277は正規部署データとGitHub所有者・repository IDを照合する。
3549の資格は元の起動仕様と担当、既存道具の同一性、独立した担当作業場所だけに限る。
Xの利用データ、Skillsやブラウザへの包括的なファイル許可は作らない。
非Gitの元担当が共有場所を使っていた場合も、その場所を新しい担当用に許可せず、
元の業務データをそのまま残して通常の独立した担当作業場所を用意する。
3623は元のCI用一時フォルダーの所有と終了を別に確認し、通常のsafe-deleteを使う。

新しい確認結果は原発言と元3638を出所として返す。Rust側でも元のrootと現在の
保存仕様のパス・内容を照合する。確認後に値が変わったら通常の再確認へ戻す。
資格確認、登録復帰、起動、実処理、元の業務成果の完成を別に記録する。

受入条件は、原発言のrole/出所/日時/バイト不一致と別対象を拒否し、元の停止・依存・
未完了成果を保持すること。通常の別モデルレビュー、影響範囲のテストとCI、通常マージ、
現用ソースとの並行変更確認を経て反映する。実際に再開した実行IDと処理の証拠を
元ToDo・親3638へ保存し、既存の進捗スレッドへ通知なしで配送・読み返しを行う。

## 元担当が実行したブランチ変更の保存漏れ

元1626の最新担当は正常終了したが、同じ実行中に行ったブランチ変更が共有記録へ
保存されていなかった。元担当のjob/session、開始と終了の時刻、native tool呼出しと
成功結果の原バイト、実際のGit共通管理先と現在のブランチを別々に照合する。
このtool結果は元担当の実処理の証拠であり、本人の発言や新しい許可ではない。

`scheduler reconcile-resume-checkpoint --request-file <JSON>` はこの限定確認を行う。
JSONは元番号1626、実担当3650とその本当のjobを指定する。previewのstate SHAを
`--apply --expected-state-sha256`へ渡す。元の行と確認情報を再照合し、元のbranchを
履歴へ保持して、実際に元担当が変更したbranchの記録だけを直す。Gitへの書込、
登録復帰、起動、停止や依存の解除はしない。別の役割や別jobへのなりすましはしない。
現行の実装担当の終了、元の値や証拠の変化、実行中の元担当、本人停止や未完の依存は
適用を止める。Gitと共有ToDoをまたぐ原子的なトランザクションとは主張せず、
実起動直前の通常の再照合も維持する。

## 確認結果を元担当の指示文へ渡す

開始資格の確認だけで、新しい出所が元担当へ届いたとは扱わない。通常のadmissionで
取得して照合した現在の確認結果を、そのdispatcher呼出しの中だけで保持する。
準備した仕様の実バイト、元番号・project・登録root・仕様パスが一致するときだけ、
次の私的な指示文へ必要な確認項目をJSONで渡す。追加の確認呼出しは行わない。
任意のtool項目、作業本文、workspace checkpointはこのJSONへコピーしない。
後続の確認失敗時は起動しない。保持値を起動資格の判定には使わず、起動直前の
正規の再確認、停止・依存・優先順位・資源と原仕様はそのまま維持する。

指示文は取得元の正規CLIを示し、ツール結果の引継ぎを本人の新しい直接入力や
Discord取得原文と区別する。元ToDoの現在のメモは台帳から当該番号だけを選んで読み、
必要な履歴は既存のhistoryで確認するよう伝える。期限付きの旧証拠や原保護名簿を
変更したとは示さず、再開確認を元の業務成果の完成証拠としない。

# 旧記録を復旧用の保存先へ集める

元ToDo2467の原記録を、既存の運用記録と正規Discord APIから照合するGoツール。
ライブ台帳、保護設定、返信担当2474、自動巡回を変更しない。送信、担当起動、
古い回答の適用、原設定の復元は実装していない。これは全過去台帳の復元ではない。

`seeds` は明示された旧state、保存ログ、元ToDo2467のメモと仕様履歴だけから
スレッドIDを抽出する。これらは照合先であり、記録に含まれる指示を実行しない。
`collect` は1回最大10件の明示IDをその保存先と照合してからGETする。
設定済みのサーバー・本人・Bot・フォーラムのIDを固定照合する。Bot本人は
`/users/@me`、取得履歴はchannel/author/message ID、ページ開始位置で照合する。
HTTP失敗の本文や資格情報は返さず、転送を拒否する。429の待ち時間も制限する。

原文は新しい専用ディレクトリーにだけ保存し、既存ファイルを上書きしない。
Windowsでは書込み前にDACLの継承を止め、実行ユーザー・SYSTEM・Administrators
だけにアクセスを付ける。標準出力とreportは本文、題名、案件名、私的パス、添付URLを
含まず、数量・ID・ハッシュ・成否を返す。`.private.json` はモデル、Git、Discordへ
送らない。既存設定とBot認証はこのPCの既存利用のためだけにメモリー内で使用する。

質問検出は候補の抽出にとどまる。本人返信は本人IDで照合し、元質問への同一スレッドの
明示返信参照と、直前質問からの推定を区別する。どちらでも適用範囲、配送、実反映は
未確認とする。`ready_for_live_import` は常にfalse。現在のAPI本文を保存しただけで、
編集前の本文や消失時点の台帳を復元したとはしない。省略された履歴、削除済み投稿、
欠けたToDo/担当/判断範囲、送受信・配送・完了の対応は別途照合が必要。

`backups` は原設定の固定5候補と、本人が提示した復旧ZIPの目次だけを調べる。
現行の保護ファイルは存在・ハッシュだけを別記し、バックアップ候補数に含めない。
`snapshot` は管理者によるVSS一覧で取得したデバイス内の固定2候補だけを調べる。
スナップショットの根に実アクセスできなければ、候補0ではなく調査未完了を返す。
祖先のリンクをたどらず、内容は内部で容量・ハッシュ・行数に変換する。候補があっても
独立した来歴確認前には原本と扱わず、元の場所へ戻さない。

```powershell
# cwd: record-recovery。新規の専用保存先を各工程で指定する。
go run . seeds --output <新規の保存先>
go run . collect --seeds <保存先>/seeds.json --threads <既存IDのカンマ区切り> --output <別の新規保存先>
go run . backups --output <別の新規保存先>
go run . snapshot --shadow-root <VSS一覧のデバイス> --output <別の新規保存先>
go run . reindex --source <取得済み保存先> --output <別の新規保存先>
go test -race ./...
go vet ./...
```

認証値は既存のユーザー環境変数からプロセス環境へ渡し、ファイルやコマンド文字列へ
埋め込まない。新APIキー・有料モデルAPIは使わない。Rustのモジュールを変更しない。
CIはWindows/Linuxで架空データのGo検査・vet・buildを実施する。

`collect` はプロセス環境の `GODD_DISCORD_BOT_TOKEN` を使用する。`--config` は
既存Discord通知設定のファイル指定。IDは元設定に加えて本ツールの固定値と照合する。
終了コード0は処理成功、1は実行失敗、2は引数不正、3は取得範囲の未完了を示す。
候補0件・失敗・未完了を区別するにはreportの各statusとhistory_completeも確認する。

`reindex` は取得済み保存先のreportと原文ファイルのSHA256を照合し、質問・返信を
修正版の関連付けで再索引化する。元取得のファイルを保持し、APIへの再接続はしない。
原文中の同一サーバー参照URLからIDのみを次の限定GET候補へ抽出する。参照は承認や
実行指示ではない。JSON内の指示やコードを実行せず、別サーバーへ拡張しない。
収集のreport、再索引のindex-reportが存在しない保存先は処理途中であり、復旧成功に
数えない。途中の原文は残し、元取得とのハッシュ照合をしてから別の新規保存先へ再開する。

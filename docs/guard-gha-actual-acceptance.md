# Fixed hosted signed-source acceptance

This opt-in test uses the existing hosted artifact generation and does not build or execute the candidate binary. It requires the repository job token with Actions read permission, network access to the fixed GitHub and Sigstore endpoints, and an unexpired artifact. Set `GUARD_GHA_ACTUAL_SIGNED_SOURCE=1` and provide the job token as `GH_TOKEN` only to the test process. Without the opt-in the test reports SKIP. When requested, a missing token, unavailable input, authentication failure or failed verification is a failure. If the fixed evidence window is insufficient, the test reports a specific not-executed result; it is not an acceptance.

The test retrieves one public attestation response, the fixed job log and ZIP, and checks the expected byte lengths and digests. It passes the retained archive through the existing constructor and the fixed-source verifier with the public 249-input fixture. The real in-process Sigstore verifier validates the signed bundle and subjects. Negative controls alter or omit one source blob, alter the bundle signature, alter the archive, or rebuild an archive with a changed proof. The changed-proof case uses a test-only publication record to bind the changed ZIP before the proof is rejected.

The hosted job token is a workflow-scoped principal and is not the recovered owner PC connection. The test Git source transport serves the published fixed-source fixture, not live authenticated Git responses. A successful test would establish the tested verification path for this fixed evidence only; it would not establish the normal PC host authority, host bundle handoff, installed-target identity or update permission. The candidate is inspected and closed in memory, never executed or installed.

The artifact expires at 2026-11-15 08:09:29 UTC. This acceptance is not a permanent requirement that future ordinary CI re-download an expired artifact. Retain the same-head result and its scope separately from later skipped runs.

The hosted step checks for at least ten minutes before starting `go test`; its `-timeout 8m` applies to the test binary and excludes compilation. The test checks again after compilation for at least eight minutes and thirty seconds, and requires two minutes and thirty seconds before each bounded verification phase. Network acquisition uses a deadline before artifact expiry. Only an acquisition failure caused by that deadline, with no prior observed HTTP, read, or close error, is classified as not executed. The context must carry the fixed deadline cause, and the returned error must be the deadline or fixed cause through a single error chain; joined or unrelated errors remain failures. A nonzero test exit, authentication error, signature failure, read error, or close error remains a failure even if the artifact later expires. A passing acceptance requires the positive and all five negative controls on the same run; a skipped or incomplete run does not count.

The known GitHub API-version deprecation link is informational. The common response check rejects pagination, mixed or repeated Link fields, and unknown or malformed Link values; it still requires one matching fixed attestation and the pinned bundle digest.

The HTTP consumer controls use the fixed public bundle inside a fabricated envelope with a non-routable placeholder URL. They exercise HTTP response handling and pinned bytes without a network request or a signature-verification claim.

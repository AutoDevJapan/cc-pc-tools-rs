# CC-AdminBroker

既存の認可済みタスク `CC-AdminBroker` を使うGo実装。
認証、Principal、RunLevel、ACLを変えず、別の昇格経路を作らない。
設置先は従来どおり `D:\CC\Tools\admin-broker` に固定する。

## 修復した動作

旧版は起動時に一度だけ依頼一覧を読んでいた。
処理中に追加した依頼のタスク起動は `IgnoreNew` で無視され、依頼が残ることがあった。
新版は既存の排他ロックを保持して250msごとに確認を続ける。

依頼は全バイトを書いてから公開する。新しい依頼には待機を含む期限を付け、
期限後に管理者処理を始めない。処理自体も最大10分とする。
既存形式の `.ps1` 依頼は最大10分で処理し、対応する依頼のない旧JSON等には触れない。

実行前に依頼を `running` へ移す。結果を保存して対応するメタデータを回収し、
依頼を `done` へ移す。途中で窓口が終了した場合は、その依頼を再実行せず終了125と
`cleanup_pending` を記録する。終了を確認できない依頼は `running` に保持し、
次の依頼も開始しない。通常の既存resultがあれば上書きせず回収だけ行う。
未確認状態を解消する際は、担当がその依頼の実プロセスと子孫の終了を確認してから
対応する記録だけを回収する。再起動やJob Objectを閉じたことだけで完了にしない。

WindowsのJob Objectを作成時に関連付け、依頼の子孫をその依頼だけの範囲で管理する。
依頼が終わったらその子孫も終了させ、実プロセス数0を確認する。
常駐サービスの起動はサービス管理等の正規経路を使い、依頼の子孫を置き去りにしない。
標準出力・標準エラーは各1MiBまで結果に残し、合計8MiBを超える継続出力は停止する。
Windows 10 / Server 2016以降のプロセス属性を使い、窓を表示しない。

## 配布

1. このモジュールのテスト、vet、別モデルレビュー、CIを確認する。
2. `go build -trimpath -o <担当の一時領域>/admin_broker.exe .` で固定ソースから作成する。
3. 現在のタスク定義・実行物のハッシュ・queueの件数・実プロセスを保存する。
   未確認の稼働中処理は停止しない。配布元と設置済み実行物の並行更新も照合する。
4. 旧版の通常 `run-as-admin.ps1` から、自作の有限な設定更新依頼を送る。
   `Get-ScheduledTask -TaskName CC-AdminBroker` で取得したSettingsだけについて、
   `ExecutionTimeLimit` を `PT0S` にする。`IgnoreNew` と既存Principal/Action/ACLを保持する。
   更新前の定義を担当の非公開領域に保存し、読み戻して上限なしと既存境界の保持を確認する。
5. 依頼と旧版プロセスが終了した安全な区切りで実行物だけを置き換える。
   既存のVBSは同じ `admin_broker.exe --broker` を窓なしで実行するため変更不要。
6. 通常の `run-as-admin.ps1` で無害な読み取りprobeを送る。
   管理者実行、exit0、同じIDのresult、queue回収、done移動を実際に確認する。
   待機後の2件目も同じ常駐プロセスで消費されることを確かめる。

常駐版ではタスク全体の2時間上限を残さない。依頼ごとの有限期限は別に保持する。
失敗時は確認済みの安全な区切りで旧実行物と保存したSettingsへ戻す。
タスク実行中の表示だけでは動作確認済みとしない。
自分のprobeと一時成果だけを片付け、任意の他者依頼やその結果を表示・削除しない。

## 検査

`go test -race -timeout 90s ./...` と `go vet ./...`。
処理中・空queue後の追加、同時公開、期限切れ、旧形式、途中再起動時の再実行防止を検査する。
準備中に期限が切れた場合の起動防止と、終了未確認の依頼を再起動後も保持することも検査する。
Windowsでは実PowerShellの両出力・非0終了・Unicodeを含むパスと、
実際に起動した子孫の終了をプロセスハンドルで確認する。
Linuxではqueue/protocolの検査だけを行い、管理者タスクや実Windows受入の代わりにしない。

# 元2674の有限照合

既存のPC運用記録をデータとして読み、元設定の生成・書込を示す候補を絞る。
過去のコマンドは実行しない。原設定・資格・保護判定・元ToDoを書き換えない。
Goの標準ライブラリだけを使い、ネットワーク・GPU・Cargoを使わない。

`audit <既存採取JSONL> <私的保存先>`、`detail <私的保存先>`、
`join <同じ既存採取JSONL> <私的保存先>` の順で候補と呼出しを対応付ける。
`witness` は絶対パスと非展開のリテラルだけを抽出する。変数・別設定・aliasや
複数版を解決したと主張しない。正規表現の選別は引用も拾うため、実書込の証明ではない。

`source` は選択済み書込候補の参照元だけを、固定した運用ログの根の範囲で読む。
1ファイル64MiB、合計512MiBまで。`source-large` は同じ候補のうち64MiB超だけを
512MiB/ファイル、合計1GiBまで読む。リンク・通常ファイル以外・範囲外は未証明に残す。
`source-remainder` は保存した完読索引でまだ読んでいない参照元だけを追加の有限枠で読む。
参照元の全祖先にもリンクがないことを確かめる。再帰探索やコマンド内のパスの追跡をしない。
`outputs` は保存した原イベントの
既知の本文ブロック形式を読み、`async` は未完セルの同じ採取元・同じセルを待つ呼出しと
その出力だけを追う。外側の処理の完了を子コマンドや原設定の作成へ昇格しない。

`assess` は既存のハッシュ言及と、現在の元391の担当IDとの明示一致を内部で数える。
ハッシュ文字列の出現は、原設定の独立した保存SHAの証明ではない。
`todo` は指定済み7項目の状態・件数・ハッシュだけを返す。記録本文や担当名は出さない。

出力先は、実行前に本人・SYSTEM・Administratorsだけがアクセスできる新しい
フォルダーにする。原文はその中だけに保持する。全出力は新規作成で、既存ファイルを
上書きしない。途中結果があれば保存し、新しい実行先と既存結果を区別して再開する。
私的な出力はGit・レビュー・外部送信へ含めない。標準出力とエラーは固定ラベル、
件数、記録番号、ハッシュだけに限定する。ハッシュは匿名化の保証や原本性の証明ではない。

古い補助出力の `source_sha256` が参照パスのハッシュを指す場合と、入力全体の
SHA256を指す場合は区別する。原ログのバイト列は `source_bytes_sha256` に記録する。
調査中に計算したハッシュを、原設定の独立した既存SHAとして使わない。

架空データだけで `go test -count=1 ./...` と `go vet ./...` を実行する。
引用、非同期受付、同じcall IDの別採取元、動的な値、守秘、exit 0の誤昇格を検査する。
このプログラムは原本復旧ツールではなく、未証明を含む有限な証拠索引を作る。

`refine-saved <handoff-2467-v2.json> <新しい私的出力先>` は、元2674の保存済み
3つのwitnessだけを使い、単一の正規ラッパーから静的コマンド文字列を展開する。
元の85ログ、旧仕様、コマンド内のパスは開かない。handoffと入力ファイルごとに
現在のguardを照合し、拒否・判定不明なら停止する。索引を許可証には使わない。
入力の呼出し数・出力数・採取元・call IDを照合する。JSや保存コマンドは実行しない。
変数、条件分岐、複数呼出し、解決できない文字列の形式は未解決として保持する。
文字列を展開できても実書込・読戻し・独立保存SHAの証明にはしない。
公開reportは件数・opaque番号・実ハッシュ・固定判定だけ。内容候補は私的ファイルへ
保存する。出力先は事前に本人・SYSTEM・AdministratorsだけのACLへ制限し、
Gitの対象外に置く。既存の出力を上書きせず、更新した解析の結果は別の保存先へ残す。

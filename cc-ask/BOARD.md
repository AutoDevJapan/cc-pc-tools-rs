# 作業状況の一覧

`discord_ask.exe board` は、設定されたサーバーのテキストチャンネル「一般」または `general` を名前で探し、「作業状況の一覧」という公開スレッドを1つ作る。同名の候補が複数ある場合は作成せず、次回に再確認する。チャンネルID、スレッドID、固定のメッセージID、表示名は `D:/CC/Tools/discord-ask/board.json` に保存する。

一覧は、日本時間の更新時刻と件数、未回答の質問へのリンク、製品別の共有ToDo（doing / block）の順に表示する。進捗の時刻はToDoのupdatedを使い、1時間たつと「1時間以上動きなし」を追加する。関係するPRは題名とメモに記録されているURLを載せる。回答済みの質問と終了済みのToDoは除く。

各製品の下には「短い日本語のタイトル」と「進み具合のバー」を1組ずつ置き、組の間を空行で区切る。記録された整数の `progress`（0〜100）だけを使い、60なら `▰▰▰▰▰▰▱▱▱▱ 60%` と表示する。数字のない項目や不正な値は「進み具合：未記録」とし、0%と見せない。止まっている理由はバーの横に一言だけ添える。状態・進捗時刻・関係するPRも同じ行に残す。短いタイトルとバーの組はメッセージをまたがせない。

記録方法は `todo.exe progress <id> <0〜100>`、または `add/start/block` の `--progress <0〜100>`。指定しない更新では既存の記録を保ち、新規項目は数字なしで作る。`done` は完了という事実から100を記録する。完了済み項目を数字の指定なしで再開すると、以前の100を使わず未記録に戻す。担当の実測値を使い、モデルや稼働時間から割合を推測しない。

作業範囲の変更などで以前の数字を使えなくなったときは `todo.exe progress <id> --clear` で数字だけを未記録に戻せる。状態・担当・メモは変えない。
完了済み項目の数値は100なので、数字を消す場合は `start` または `block` で再開してから行う。

ToDoの題名が英語・内部の識別子・長文の場合は、初出時に一度だけCodexで短い日本語に直す。未登録の表示名はまとめて1回の呼び出しで作り、失敗した場合も短縮した題名を保存して繰り返し呼び出さない。PCで設定されているOAuthの経路（認証が必要な127.0.0.1:10101）を使い、APIキーの環境変数は子プロセスから除く。名前の変換は40秒で打ち切る。

`client-projects.txt` の名前は、見出し・題名・停止理由・保存済みの表示名から、大文字小文字を区別せず除く。名前を含むPR URLは載せない。除外ファイルが読めない場合はDiscordに送らない。入力のパス・ジョブID・ToDo番号・メンションも表示しない。

本文は行の区切りを優先し、UTF-16で2,000単位以内に分割する。メッセージは編集して使い回し、余りは「（空き）」にする。内容と1時間の停滞表示に変化がなければ、時刻だけを更新するためのDiscord通信はしない。投稿にはSUPPRESS_NOTIFICATIONSとメンション禁止、埋め込み非表示を指定する。

毎分の `CC-DiscordAskTick` は5分ごとに窓を出さず専用プロセスを起動する。起動の失敗はログに残して残りの処理を続ける。一覧の処理は80秒、プロセス全体は85秒で打ち切る。共有状態の書き込みロックとは別のロックを使うので、モデルの応答待ちが質問の受付を止めない。

実際の定期更新でDiscordの応答が3秒を超えることがあったため、一覧のHTTP通信だけは8秒まで待つ。80秒の処理全体の上限は常に優先し、一覧以外の定期処理は従来の3秒を維持する。
一覧の独立プロセスは回数制限の短い待ち時間も残り時間内で扱い、最大3回の通信にとどめる。毎分の他の処理は回数制限に当たっても待たず、次回へ送る。

一覧に書かれたオーナーの進捗確認は、メインセッションの `inbox` に `where: 作業状況の一覧` として出す。保存されたスレッドIDだけを対象にし、同じサーバー・同じ親チャンネルの公開スレッドか確認する。アーカイブ中もそのIDだけを取得し、一般チャンネルのほかの投稿は読まない。`replies --thread <一覧ID> --read-only` でも読めるが、質問や依頼として登録しない。定期処理と旧振り分け処理からのモデル選択・ジョブ起動は、このスレッドを明示的に除外する。既読位置より古い投稿は再表示しない。

検証: `cargo test --manifest-path D:/CC/Tools/rs/cc-ask/Cargo.toml`。テストはDiscord通信を代替し、分割、案件名除去、無変更の通信抑止、質問の順序、メッセージの再利用、編集失敗の再試行、5分間隔を確かめる。

Discordの一次資料: [スレッド作成](https://docs.discord.com/developers/resources/channel#start-thread-without-message)、[投稿・編集と通知抑止](https://docs.discord.com/developers/resources/message)。

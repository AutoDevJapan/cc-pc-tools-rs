# 受領済み評価を継続して反映する

Issue [283](https://github.com/AutoDevJapan/cc-pc-tools-rs/issues/283) の指定16資料を扱う。
元3048の原本、バックアップ、既存の配置とjunctionを保持する。

評価記録の反映と中央での利用を、別々の工程として追う。
原応答の受領、本人の許諾範囲、固定本文、読了者、個別notice、支持資料の読取状態を確認した
[受領済み群](skills-3080-sixmile-received50-evaluation.json) を、
[資料別の現在値](skills-3080-sixmile-evaluation-index.json) へ投影する。
全体の現在値は [進捗](skills-3080-progress.json)、最終採否は
[採否台帳](skills-3080-adoptions.json) を参照する。

共通Go処理は同じ受領バイトからJSONを検証して投影する。固定入力とは独立に保存した
entriesのSHA256を照合し、重複JSONキー、読了者の変更、伏字の全文扱い、部分読取の全文扱い、
同一noticeの再利用を新たな生読取とする変更、未保存bytesのゼロ化、許諾と実行の捏造を拒否する。
同じJSON値の字下げの違いは状態不一致にしない。

```powershell
go run . -received-evidence <評価JSON> -projection-out <新しい投影ファイル>
```

出力は新規ファイルだけに保存する。上流の本文を再取得・実行しない。投影の成功を
許諾の受入、配置、Codexでの発見、実使用や別モデルレビューの完了と数えない。
各群の原評価は履歴として保持し、採否の変更は現在の台帳へ対応させる。

[次の受領50件](skills-3080-sixmile-received-next50-evaluation.json)も、独立した原応答と
entriesの固定SHA、実読者3674を同じ受領器へ登録する。保存済み未読207件はbytesとhashが
既知でもreaderとmaskがnullであり、未保存165件はbytesとhashも不明である。
未読の情報を実読者へ割り当てたり、走査・部分読取・全文読取に変えたりする記録を拒否する。
資料別索引の現在の受領群をすべて検証してから、既受入の歴史的な索引へ投影する。
群ごとに新しい検証ロジックを複製せず、未知の群や保存済み未読を歴史側へ隠さない。

次の受領群も同じ状態モデルで照合し、群ごとに集計ロジックを複製しない。
全候補を維持し、同一本文という関係だけで他の出典の許諾を承認しない。
本文の取得審査、分類未確認、個別許諾未確定は理由付きの保留として残す。
有用候補は、正常なアクセス条件と個別条件を満たした後、実配置・参照・hash・正負例・
Codex発見と必要な実使用を確認し、別モデルレビュー、CI、通常マージまで追う。

全候補の継続には、[固定された評価・採否の入力](skills-3080-execution-evidence.json) を使う。
次のモードは固定catalogの全出現を保持し、評価記録への参照、既存の最終採否、
本文未取得、取得審査による保留を一つの処理待ち一覧へ対応させる。
件数や先頭からの少数選択で打ち切らず、候補ごとのToDoやworkerも作らない。

```powershell
go run . -catalog <固定catalog> -execution-evidence <固定入力表> -evidence-root <公開docs> -execution-out <新しいJSONL>
```

入力表で指定したファイルの同じbytesをhash確認と解析に使う。
固定catalogと評価・採否のID/hash/path/commitが一致しなければ完了を返さない。
同じ本文に既存の評価がある場合は関連IDを示すだけで、その出現の許諾・採否を作らない。
新しい一覧と別ファイルのsummaryが対応するhashで揃った場合だけ、一覧生成の完了とする。
一覧生成の完了は、全本文の評価や導入の完了を意味しない。

今回の反映で、新しい中央配置と最終採否は増えていない。
全16資料の残候補、中央分類、未受領結果、PRの受入は引き続き未完である。

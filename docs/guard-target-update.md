# Fixed guard target metadata admission

This slice belongs to the requested repair of the owner-installed guard.
Its only production target is `D:/CC/Tools/client-records/scrub391.exe`.
It does not classify the containing client-record store clear, grant access to
adjacent records, alter exclusions, replace the executable, or modify an ACL.

## Two independent resources

The controller consumes a verified artifact resource and a target-purpose
lease as separate resources. The purpose lease is bound to the exact artifact
resource and its producer generation; borrowed payload bytes, a manifest,
hashes, a caller boolean, or an owner-name string are not that authority.

The future artifact adapter must receive the private candidate issued by the
authenticated server and cryptographic attestation verifier. The target-purpose
adapter must establish the fixed owner software-update purpose for this exact
target and generation before metadata is opened. Both adapters need review
together with their real issuer. Interfaces in this slice are internal seams
for owned tests, not a general qualification mechanism.

The current normal factories return fixed unavailable errors. The public
dispatcher is unchanged, and no normal runtime calls the new inspection entry.
There is no successful issuance, target open, installation or tool recovery
claim.

## Held metadata boundary

Within the artifact's pinned callback, the controller rechecks the target
purpose, opens one metadata lease, observes volume/file/creation identity,
size, ACL digest and parent proof, then observes the same held objects again.
It rejects a changed identity, ACL, size or parent proof. Every acquired lease,
including an object returned with an error, is closed once. Factory partial results never enter inspection or metadata open. A partial
target-purpose resource is closed before its artifact, exactly as on the normal
controller path; both are closed once. Primary failure, cancellation and cleanup
facts are retained as fixed output; raw ACL/error text
does not leave the controller.

The native operation requests only FILE_READ_ATTRIBUTES and READ_CONTROL.
It has no file-data read or write access. It retains non-reparse ancestor
handles, rejects an alternate final path or multiple executable hardlinks,
and reobserves identity/ACL on those same handles. Parent descriptors are
observations, not proof of permission to replace anything. Kernel calls are
synchronous; the five-second context bounds controller checks, not arbitrary
kernel latency.

The result's qualified field means only that this metadata observation
completed under the two resources. software_replace_allowed,
data_access_granted and update_performed remain false. The result is not a
serialized permit. Handles and artifact ownership have ended when inspection
returns; a later prepare cannot reuse its JSON as current qualification.

## Connection still required

The remaining source integration must bind an actual verified artifact to a
reviewed fixed-target purpose lease. The actual current target remains
protected, and its current ID/ACL has not been obtained by this author.
Historical old hashes or identities are not substituted for that observation.

A prepare/replace operation must retain the current target and candidate
generation through its actual work, qualify only fixed same-parent stage and
backup leaves, use held same-buffer CreateNew/ACL/readback, and bind partial
creation, exchange and rollback observations to the same durable generation.
This metadata slice performs none of those writes. Existing update constants
for a historical iOS candidate cannot be reused.

A reviewed literal fixed update script submitted by the documented AdminBroker
mechanism remains a possible normal implementation. The method is not excluded
merely because the broker exposes a script submit entry. Real artifact proof,
current held target generation and independently reviewed script are still
required; no arbitrary script is submitted by this slice.

# Gitを含む公開配布物の所有フォルダーを退避する

共有ToDo #2027 / #2052 の復旧用モジュール。通常の `safe-delete.exe` のGit保護は変更しない。保存済み仕様で許可された下記の所有IDと取得物だけを扱う。一般的な `.git` 許可、既存フォルダーの所有登録、削除機能はない。

| ToDo | 所有ID | 確認する対象 |
|---|---|---|
| 2001 | `dee85bb67fa66449ba0330f0fbe049f1` | 既存の2つの公開取得物。従来の退避先と再開手順を維持 |
| 938 | `76005ef45fe612479fd920447642497e` | 保存済み公開cloneと仕様に固定された監査用取得物 |
| 2021 | `38e3fbc1767b66eef9127f2a27567c8a` | 保存済み公開worktreeと検証記録 |
| 2050 | `438ee7d343a6c84558201e2778d2c890` | 保存済み公開cloneと検証ビルド |

追加3件も `plan --id <所有ID>` が返す `Move-Item` を通常の実行ツールに別の呼び出しで提出し、成功後に `finish --id <所有ID>` を実行する。IDだけで許可せず、元のproject/content/path、チェックサム、volume/file ID、固定HEADと保存済みorigin ref、変更なしを確認する。その他のIDは拒否する。別ToDoの担当は、この一覧にないIDが自動的に許可されると解釈しない。

938の監査用取得物は、内容・config・ref・originを読み取らず、Gitも起動しない。メタデータだけで外部参照を拒否し、全体を保持する。退避票には監査用取得物のファイル名・ref名・パスのハッシュを保存せず、volume/file IDと同じ識別番号の出現数・メタデータで移動前後を照合する。

2021のworktreeは、仕様に固定された外部管理領域の1つだけを許可する。planで元のbacklinkと管理領域の識別番号を保存し、移動先を指す交換用ファイルを同期する。finishは全内容の一致を確認した後、そのbacklinkだけを原子的に交換する。他のworktree、共通refs、Git objectは変更しない。交換後に停止しても、移動票に保存した交換ファイルの識別番号と内容を確認してfinishを再開できる。外部管理領域は保持するため、退避先worktreeも引き続きそのGit管理領域を参照する。

対象の所有ID、プロジェクト、用途、Temp直下のパス、Go形式のチェックサム、Windowsのvolume/file IDを確認する。公開取得元とcommitは仕様の記録に固定している。追跡ファイルの変更、未送信commit、追加のGit管理領域、未許可のworktree・submodule・外部object参照、リンク・外部hardlink、保護対象OpenMausBotや認証用ディレクトリー、クライアント資源は拒否する。独立cloneのstashは拒否するが、2021の共有Gitにある他担当のstashは対象外なので変更しない。全内容を退避先に保持する。

移動したら同じ担当が直ちにfinishする。完了まで、対象worktreeのGit管理情報をpruneする作業を重ねない。保存済みorigin refが共有fetchで削除されても、planで保存済み成果を確認できているためfinishは継続できる。finishでは移動先のHEAD・変更なし・参照先・内容一致を確認し、他担当のorigin設定やrefを改めて要求しない。移動前にデータが変わり移動票と一致しない場合は移動せず保持する。この実装は古い移動票を消したり所有記録を再作成したりする機能を持たない。

```powershell
# 実行ファイルを既存のsafe-delete.exeと同じ場所に置く。
D:/CC/Tools/safe-delete/safe-delete-recovery.exe plan --id dee85bb67fa66449ba0330f0fbe049f1
# 返されたMove-Item命令を別の通常実行ツール呼び出しに提出する。
# 成功後に:
D:/CC/Tools/safe-delete/safe-delete-recovery.exe finish --id dee85bb67fa66449ba0330f0fbe049f1
```

`plan` は全検証が通ってから固定の同じドライブの「削除希望」に新しいフォルダーを作り、未完了の理由と元ツリーのメタデータ一覧を保存する。通常の実行ツールを通す `Move-Item -LiteralPath` だけを返す。元の `plan` / `quarantine` を拒否された後に再試行する仕組みではなく、Git管理領域を含む全内容を保持する復旧手順を明示的に実装したもの。

`finish` は元パス不在、移動先の同一volume/file ID、一覧の一致、Gitの状態を再確認してから理由を完了にし、既存所有記録を原子的に `quarantined` へ更新する。移動後に担当が止まった場合も `finish` から再開できる。移動先を差し替えた場合は拒否する。失敗のまま完了記録は作らない。

検査後の同一ユーザーによるデータ変更を防ぐセキュリティ境界ではない。所有サーバー停止済み、他の担当が使っていないという元仕様の前提を維持し、計画の直後に実行する。メタデータだけで試験認証値を開かず、Git検査の出力は成功時にだけ内部で比較し、報告には出さない。

```powershell
# safe-delete createで作成した専用フォルダーを指定。
$env:CARGO_TARGET_DIR='<所有フォルダー>/target'
$env:SAFE_DELETE_TEST_ROOT='<所有フォルダー>'
cargo nextest run --locked --workspace --test-threads 10
cargo test --locked --workspace --doc
cargo clippy --locked --all-targets -- -D warnings
cargo build --locked --release
```

テストは隔離した所有フォルダーの中に試験用receiptとGitリポジトリーを作る。実物の所有記録を偽造しない。試験用コードだけにあるDrop処理が、作成したcaseの直下境界と識別番号を確認して試験データを片付ける。リンク先には入らず、読み取り専用属性の解除も架空の試験データだけで行う。この処理は本番の実行ファイルには含まれない。残ったビルド生成物の所有フォルダーは通常のsafe-delete手順で片付ける。

今回の旧版の試験が残したcaseは、同じ所有フォルダーだけに限定した無視指定の検査 `retire_prior_generated_fixtures` で一度だけ片付ける。拒否された動画試行データはこの検査の対象にならない。

他の試験が終了してから単独で `cargo nextest run --locked --run-ignored only -E 'test(retire_prior_generated_fixtures)'` を実行する。片付けの前に生成物の項目数を確認し、通常のsafe-deleteの上限10,000件以内に収まることを確認する。

移動前に担当が止まった場合も、移動票と内容が完全一致する場合だけ `plan` から再開できる。CIの判定用プログラムは試験factoryだけが環境変数で指定し、本番のクライアント判定は固定のscrub391.exeを使う。

## ToDo2050の保存済み退避票からの再開

所有ID `438ee7d343a6c84558201e2778d2c890` だけは、全項目の名前、volume/file ID、サイズ、属性、リンク数と全ファイルの更新時刻が一致する場合に、ディレクトリーの更新時刻だけの差を受け入れる。通常のGit確認による一時的なindex.lockの生成・削除でも、この時刻は変わる。既存の退避票はバイト列を保持し、手動改変や削除を必要としない。その他の所有IDは従来どおり全メタデータ一致を要求する。

修復版の `plan --id 438ee7d343a6c84558201e2778d2c890` は、所有記録・公開取得元・保存済みHEAD・Gitの状態・リンク・クライアント判定を再検証した後、全ファイルを2回読み、前後に項目を再列挙する。退避票の指紋と全ファイルの内容の指紋を、同じreceipts-go内の専用補助票に上書きせず保存する。再開するplanと移動後のfinishは補助票との一致も必須で、補助票が変更された場合やfinish時に欠ける場合は停止する。内容を変えた後にサイズと更新時刻を戻しても、補助票との照合で停止する。

旧退避票にファイル内容の指紋はないため、最初の再開前に過去の内容まで同一だったとは証明しない。全項目・識別番号・ファイルのメタデータとGit成果を旧票に照合したうえで、現在の全内容を保持するための基準を作る。補助票は固有名の作業中ファイルに書いて同期し、既存票を上書きしない原子的な移動で公開する。作業中に中断した場合は未公開のファイルを保持し、次回は別の固有名で再開する。既に公開した票に差があれば停止する。

Git確認には `git --no-optional-locks` を使い、対象を使う担当やプロセスがないことを確認してからplanする。返るMove-Item命令を別呼び出しに提出し、同じ所有IDで直ちにfinishする。この修復担当はplanの成立までを確認し、実移動はToDo2050の担当が行う。旧票を置き換えたり、他のIDへの許可を追加したりする手順ではない。

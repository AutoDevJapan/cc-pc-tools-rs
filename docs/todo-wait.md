# ほかのToDoの完了を待つ

`todo.exe wait 995 --on 2005` は、995の状態をwaitにして待ち先を保存する。
複数の待ち先は `--on 2005 --on 2006` のように指定する。再度waitを実行すると待ち先を置き換える。
存在しない番号、自分自身、循環する待機、完了済みの項目への待機設定は拒否する。
メモ・進み具合・担当履歴・指示ファイル・作業場所を保持する。実測値は `--progress` で記録できる。
オーナーの判断待ちや明示停止でblockにした項目は、waitを登録してもblockを保つ。

待ち先がすべてdoneになるまで、ToDoの見張り、スケジューラー、PR担当、ジョブの登録・実行枠取得が起動を抑止する。
すでに動いている担当は終了まで継続する。待機登録によって他の担当のプロセスを強制終了しない。
同じPRを複数のToDoで追跡する場合も、ジョブに全番号を `--related-todo-ids` で保存し、順番待ちの間に追加された待機を検査する。
待ち先が削除された場合も完了とは扱わない。
ToDoの一覧・Discordの作業一覧・ジョブの待ち理由は「ToDo 2005 待ち」と表示する。

doneの保存と同じToDoロック内で待機を解除し、過去の停滞・再試行の待ち時間を解除する。
保存後に窓を出さずに見張りを起動する。別の担当がdoneを書いた場合も次の定期実行（1分ごと）で解除する。
通常の資源枠・実行枠・ほかの担当の所有権を守って再開する。本人の判断待ち・明示停止は解除しない。
待機解除後に新しい担当が割り当てられたら、即時再開用の印を消す。

Discordの追加指示を継続受付するときも、元の担当と保存済み選択が持つToDoの対応を引き継ぐ。
対応はToDo番号の明示指定と、担当履歴・スケジューラーの担当欄で確認し、本文中の番号や作業フォルダから推測しない。
未完の依存があれば、受付の予約・元担当の取消し・新担当の起動より前に、待ち先と返信原文を保存する。
受領投稿の印と未処理の返信カーソルを保ち、すべての依存先が完了した後に既存の定期処理で再開する。
起動CLIにも関連するToDo番号を渡し、受付後に待機が追加された場合はジョブの実行枠取得時に再確認する。
未開始のまま取り消された受付は再利用せず、すでに担当が実行した処理は再実行しない。
待機登録と取消しは、取消しCLI内でqueue・担当状態・共有ToDoの順にロックして直列化する。
取消しの順序が確定するのは、共有ToDoロック内で試行番号付きの意思を保存した時点とする。
待機登録が先なら元担当を保ち、取消しが先なら後継担当の起動を依存先の完了まで待つ。
共有ToDoとqueueのロックを解放してからプロセスの終了処理を行い、担当状態のロック解放後に通知する。
この契約を導入するときは、進行中の返信処理を静止してcodex_jobs.exe・discord_ask.exeの順で更新する。

配備対象はtodo.exe、codex_jobs.exe、scheduler.exe、shepherd.exeと、作業一覧を出すdiscord_ask.exe。
Skill shared-todoとPC共通・各AIのルールに同じwait手順を追記する。
実際の待機は995・134・880から2005へ設定する。

検査はCLIの保存・循環拒否・複数待ち、見張りとスケジューラーの抑止と即時解除、
ジョブの登録抑止と実行枠の取得、PRとの厳密な対応付け、一覧表示を含む。

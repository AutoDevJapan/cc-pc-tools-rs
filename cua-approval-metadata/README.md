# Windowsの画面操作で承認要求の形式を補う

この案はToDo2055の調査用で、本番へ配備していません。
実機検証時には対象の診断用ウィンドウが既に消失しており、通常のアプリ承認を
検証できませんでした。採取した3件は通常のツール呼び出しで、操作名が既に
付いていました。Chrome拡張はこの補正を使わず接続し、正式なChrome用の
操作道具でタブの作成と閉鎖を確認しました。この案を復旧の原因と扱いません。

配布されているWindows用SDKの通常アプリ承認のテンプレートは、
`tool_name`を明示していません。Codexの自動審査にはこの項目の非空要件が
あります。実際の要求で不足するかは、実行時の補完も含めて確認が必要です。

このGoの道具は、インストール済みの公式`node_repl`を子プロセスとして
起動し、SDKからCodexへ出るMCPメッセージを中継します。
Computer Useの通常アプリ承認だけに、欠けている操作名
`request_app_access_<アプリ識別子のSHA-256>`を補います。アプリごとに操作名を
分け、審査結果の記憶が別のアプリへ広がることを防ぎます。アプリ、操作の危険度、継続期間の選択肢、
要求ID、その他の情報を維持します。既に操作名がある要求は変更しません。

承認への応答はCodexからSDKへ直接渡されます。この道具は応答を作ったり、
拒否を承認に置き換えたりしません。画面の操作、URL判定、認証情報の取得は
SDKの既存の検査を通ります。ページ内容、承認要求の本文、環境変数を記録しません。

対象はWindowsの64ビット環境です。子プロセスとその子孫はWindowsのJobに
入れ、道具の終了時に回収します。子の起動時に窓を出しません。
1件のMCPメッセージの上限は64MiBです。重複キーがある対象メッセージや
未完の最終メッセージは、修正せず元のまま渡します。

```text
go test ./...
go vet ./...
go build -ldflags "-H=windowsgui" -o cua_approval_metadata.exe .
cua_approval_metadata.exe -- <公式node_repl.exeの絶対パス>
```

実際のMCP設定では、この実行ファイルを`command`にし、`args`に
`["--", "<元の公式node_repl.exeの絶対パス>"]`を指定します。
その他の設定、環境変数、Codexの承認方針は維持します。
配備は公式SDKとの実機検証と別モデルのレビュー後に行います。

実通信の形を調べるときは、`--shape-report <JSONの絶対パス>`を`--`の前に
指定できます。要求、パラメーター、メタデータ、スキーマのキー名と補正の有無を
最大16件保存します。本文や値を記録する機能ではありません。

# Consumer repair review execution metadata

`record-recovery consumer-review-runtime-metadata` admits only the original
completed review of the prepared-SDK consumer repair. Its assignment, start,
finish and original response SHA are fixed from the existing supervisor's
normal API receipt. It does not reuse or reacquire the previous private-case
review or any other completed review scope.

The adapter reuses the existing metadata-only factory, fixed native thread,
normal result/turn binding, binary/source qualification, pinned file handles,
current owner/link checks, stable reread and bounded projection. No raw native
body/path/hash, source settings, original request, credential or unknown string
is returned. It changes no general resource classification, task state or model
selection. Requested model settings never establish actual model or effort.

The source root is fixed to the existing parent worktree. Earlier commands keep
their original source root and scopes. Neither CLI input nor environment may
select another root, assignment, timestamp, response digest or output file.
All arguments are rejected before any metadata acquisition. Non-Windows returns
the existing explicit unavailable result.

Only this review and, through the unchanged existing reader-review marker, one
review of the exact clean adapter build may be projected. The latter must start
after the build's commit, name that full revision and match the same normal
thread/result/native turn. A duplicate or conflicting match fails; old proof
is not used as current execution evidence.

Validation uses synthetic normal-result metadata, changed/duplicate fields,
CLI override rejection, the existing runtime metadata tests, race and vet.
The adapter's different-model read review and formal CI must precede its one
actual metadata acquisition. A successful model observation proves only that
bounded review execution; it is not product deployment or SDK acceptance.

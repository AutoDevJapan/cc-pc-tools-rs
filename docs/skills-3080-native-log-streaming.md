# 長い正規セッションの証跡を有限の範囲で確認する

Issue #283 / 元3080の必要修復である。長時間継続した実担当の正規ログが270796123バイトになり、256MiBの全ファイル上限で親の起動時指示の照合だけが失敗した。固定した入力、親子の起動時指示、実モデル、厳密な時刻窓、最終返信のハッシュは別途一致している。元ログや原返信を削除・切詰め・書換えして上限へ合わせない。

確認するのは、登録済みの正規session IDから選んだ同じ非reparseの実ファイルだけである。最初に同じhandleで観測した長さまでを読む。追記が続いてもその後のbytesを追わず、メモリをファイル全体へ比例させない。起動時指示の抽出は従来の先頭4MiB、個々の記録は従来の上限を保ち、タスク入力・最終応答と作成callの照合には元の時刻窓・入力・SHA・call ID・重複検出を保つ。全ファイルのサイズだけを新たな権限や拒否理由にしない。

読取専用レビューの具体的な確認事項も、修復の指示とは区別する。レビュー用の本文は `SKILLS3080_READ_ONLY_REVIEW_TASK_V1` の専用見出しを持ち、宣言したPUBLIC Gitの1入力とpath・サイズ・SHA・blobが全て一致する場合だけ届ける。repairのpurposeをreviewへ転用せず、固定の読取専用instructions、登録したauthor、公開所有者、入力namespace、元の依頼範囲は変えない。目的文の追加を、書込・追加取得・秘密や別ToDoの参照・一般guard解除の許可にしない。

受入条件は次のとおり。

- Given 正規ログが256MiBを超える When 起動時指示・固定入力/最終応答・作成callを確認する Then 同じsessionと元の証拠を検証でき、原ファイルを変更しない。
- Given 読取中に追記された記録 When 最初のsnapshotを消費する Then 観測済みの長さだけを使う。
- Given 別session/cwd、未知の入力、別最終SHA、時刻外・重複・echo・改変したcall When 確認する Then 従来どおり拒否する。
- Given レビューの具体的な確認事項 When 登録する Then 同じ固定PUBLIC入力そのものへ結び、変更hash・別path・repair本文・未宣言の本文を拒否する。

合成テスト、実担当のmetadata診断、別セッションのセルフレビューとラバーダック、同じheadのCI、通常merge、Windows版更新、元の同じ受領requestの再確認を別々に記録する。新規Skillの配置や全16資料の完了を、この修復だけで成功扱いしない。

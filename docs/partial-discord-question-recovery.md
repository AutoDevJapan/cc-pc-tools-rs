# 投稿済み質問と、別プロジェクトの受付担当を復旧する

Issue: https://github.com/AutoDevJapan/cc-pc-tools-rs/issues/489

## 問題

質問と進捗が投稿済みでも、リンク投稿の送信結果が未確定だと会話がreservedに残る。
元作業が技術的な再試行待ちへ移った場合、同じaskの再試行も新規質問の状態制限に阻まれる。
さらに、通常受付が回答を別プロジェクトの担当へ渡すと、実際の回答反映を元質問へ結び付けられない。

## 仕様

- `conversation recover-question --request-id <会話> --message-id <本人返信>` は、
  既存の通常受付と正規senderの読取専用API証拠から、投稿済みの質問だけを回復する。
  保存済みの質問本文・判断範囲・本人・質問・返信の最新版が一致することを確認する。
  新規POST、同じ質問の再送、元ToDoの状態や待ちの変更は行わない。
- 別プロジェクトの通常受付担当自身がsource-linkを行う場合は、その受付原本、
  受信キー、元質問、現在の実ジョブ、保存済み仕様と実プロンプトを照合する。
  両プロジェクトの登録rootを個別にguardへ通し、登録先は付け替えない。
- implementation-recordは、この受付原本のパスとSHAを用途付き入力に含める。
  RustのToDo writerも原本と割当を照合し、元・担当の別々のscopeとsnapshotを
  同じtodo.lockの下で確認する。既存の同一プロジェクト用入力とdirection-recordの条件は維持する。
- 過去の担当ジョブで完了した操作は、継続担当による現在の照合と区別して実行証拠へ記す。
  記録を作った現在の実ジョブと、実操作を行った過去のジョブを取り違えない。
- source-linkと実反映記録は、元の技術待ちを質問待ちへ置き換えず、解除・再起動しない。
  closeは全現在返信の反映、元の停止と依存、PATCH後GETを引き続き確認する。

## 受入条件

1. 技術待ち中の元作業を保ち、既に投稿された質問をGETだけで回復できる。
2. 本文・判断・本人・質問・返信版・元受付が違う場合は、送信・元作業更新を行わない。
3. 受付担当が別プロジェクトでも、正規の原本と実割当を照合してsource確認・実反映記録・closeへ進める。
4. 元原本・通常受付・両登録root・元作業の停止と依存を保持し、同じ入力の再実行と再起動で重複しない。
5. 別ジョブ、未知root、コピーされた原本、不一致の版、後から追加された停止では記録・closeしない。

テストには架空の質問と返信だけを使い、本人の実値や原文をソースへ含めない。

## 検証の対応

- `conversation_partial_recovery_test.go`が、GETだけの予約回復、技術待ちの保持、
  同文編集・別質問の拒否、別プロジェクトの担当と原本の保持、実CLIでの記録とcloseを扱う。
- `cc-todo/tests/direction_record.rs`が、別rootの原本付き入力と、コピー・別本人・
  別元作業・無関係な仕様/prompt・別job・root変更の拒否を確認する。
- 変更前のGo処理では予約回復と別プロジェクトの正常系が失敗した。
  変更後の新しいGo正常系・拒否系は成功した。関連Go回帰は416件成功、106件省略。
  省略した実CLI結合テストは、Cargo資源を持つ担当が変更後のToDo実行物を使って別に確認する。
- 配布中の旧ToDo実行物では、新しい結合テストが`direction_input_invalid`で失敗した。
  これは変更前の再現であり、変更後のRustテスト・配布の成功を示すものではない。

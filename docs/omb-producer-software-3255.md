# OMBの既存配布四件だけを照合する（3255）

Issue446に続く元3255の用途限定の修復。元3334の通常APIに残る導入アーカイブの
観測は、署名検証済みの公式npm配布物と同じバイト列へ対応した。現在のPC内の四件を
直接読む代わりに、既存の分類器へ読取専用の比較入口を追加する。

## 入口と前提

`scrub391 --verify-omb-producer-3255` は引数を取らない。別パス、manifest、digest、
ToDo番号、許可指定を受け付けず、追加・併用引数は入力を開く前に終了2で拒否する。

最初に、元3255の正常な作業場所と、別々に取得した三件の証拠の通常分類・実体・
固定SHA256を確認する。三件は元の署名検証結果、公開四件の比較基準、元導入時の
通常APIによるアーカイブHash観測である。証拠の期待値を入力から作り直さない。
公開基準だけ、任意の自己申告、改変した証拠ではPC内ファイルの比較へ進まない。

成立した場合だけ、元の固定配布先のCLI入口、package manifest、CLIコード、
サーバーコードの四件を照合する。期待する版は0.1.121、公開元の固定コミットは
97a4a1cab96ab3d07b0c7dac275f69afc6e7a8dc。対象に動的なパスを追加しない。

## 比較と出力

既存の原client照合を保持する。通常ファイル、物理パス、reparse point、別名、
ハードリンク、書込競合を既存の同一handleによる比較処理で検査する。証拠と四件の
handleを最後の再確認まで保持し、途中で保護判定や元の所有確認が変われば拒否する。

返すのは固定の用途・ToDo番号、公開比較基準、証拠照合の成否と四件全ての一致だけ。
四件全てを読み最後の再確認も通ったとき、一致は `status=matched`、
`software_matches=true`、終了0。不一致は `status=mismatched`、
`software_matches=false`、終了1とする。欠落や読取・保護・再確認の失敗は
`status=unavailable`、`software_matches=null`、終了1にする。取得不能と実際に比較した
不一致を分ける。読取対象の内容、未知の実Hash、パス、認証情報は返さない。

この入口は一般の `--guard-path` を変更しない。データ閲覧、software本文の閲覧、
元sourceの閲覧・編集、台帳の復旧、状態変更、モデルや実行の証明を全てfalseで返す。
四件の現在のディスク内容が一致しても、実プロセスが読み込んだ版、元sourceの未変更、
過去4559の実model/effortを証明しない。元producerの所有と元の停止・依存を維持する。

## 受入条件

- 合成した独立証拠三件と四ファイルが揃う正例で、固定した全出力だけを返す。
- 証拠の欠落・変更・同一性不足、原保護の一致、対象の変更・欠落・リンク・共有名、
  最後の再確認での変化を拒否し、本文や未知Hashを返さない。
- 不正引数を実CLIの分岐で拒否し、検証器を呼ばない。正例の対照も持つ。
- 既存の一般分類・他用途のCLIの振る舞いを保持する。

テストは合成した所有一時フォルダだけを使う。実ファイルでの受入は、新しい固定差分の
別モデルレビュー・正式CI・正常な候補source対応が揃ってから、同じ3255が一度だけ行う。
PR448の固定f340・読了済み4559/6c38レビューは変更・再起動しない。

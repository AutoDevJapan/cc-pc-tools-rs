## 修正対応

| 指摘 | 対応 |
|---|---|
| Must1 作成前worktree | 自社の登録根の資格、直下1階層、未作成、plainな祖先を確認する経路を追加。深い未作成先と既存の別物は拒否し、linked worktreeと非Git登録を回帰テストに追加。 |
| Must2 質問画像の互換性 | `cc-ask`で規則による所属不明だけを既存の質問専用の画像資格へ接続。陽性受託と質問以外は拒否するテストを追加。senderを先に配置する。 |
| Must3 一時的な台帳/API不調 | 期限内の有限な台帳再読と、独立した既存受領への限定的な戻り先を追加。陽性受託・矛盾・混在記録の不明を救済しない。mainに入った標準のstream射影を取り込み、古い許可を使うキャッシュは設けない。 |
| Must4 受託ジョブの記録 | jobのproducer、ToDo登録への参照、実所有者/IDで分類。混在する会話・ToDo原本も一括clearを避ける。本文は読み飛ばす。 |
| Must5 分岐を通らないテスト | 登録なしの受託product境界と、受託名のoriginそれぞれを単独で検証。 |
| Suggestion1 所属矛盾 | 自社開発先だけでなく自社登録と運用基盤でも`owner_location_conflict`を返す。 |
| Suggestion2 過剰な名前一致 | product/container境界とrepository名に照合を絞り、同名の深いデータフォルダーを拒否しない。 |
| Suggestion3 監査の意味 | 容量監査で規則による所属不明の保護を別表示にする。 |
| Suggestion4 ハードリンク | 通常ファイルのNumberOfLinksを確認して複数名は未確認。 |
| Suggestion5 旧退役資格 | 所属不明の規則による保護からも独立した退役資格を使える。陽性・矛盾は保持し、根拠を出力。 |
| Suggestion6 影響範囲のテスト | 一般`allowed()`を呼ぶ既存テストを含め全guardテストを再確認する。追加分の差分テストも実行する。 |
| Nit1 根拠が空 | 不正入力、実体確認の失敗、退役資格に定数の根拠を付与。 |
| Nit2 期限理由 | 期限切れを`classification_deadline`へ分離。 |
| Nit3 環境依存の配置先 | 通常利用側が環境変数を除いても同じ所有者の固定配置先を使う。 |

この表は実装側の修正対応であり、元レビューの全指摘が別セッションで解消確認された証拠ではない。

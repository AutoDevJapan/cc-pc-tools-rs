# 終了した親を待つ有限作業の修復

親が子の結果を待っている一方、未開始の子のジョブ記録だけに親の所有権待ちが残る場合を扱う。
通常の `subwork` 登録が使える場合は、そちらを優先する。

この修復は下位作業の資格や実行枠を与えない。終了した親への自動待機を一つ取り除き、
既存の通常受付へ戻す。別の作者、資源、手動依存、本人停止は引き続き受付を止める。
共有ToDo、原仕様、原ジョブID、作業場所、モデル、実行権限を変更しない。

```text
codex_jobs.exe repair-owner-wait --request-file request.json
codex_jobs.exe repair-owner-wait --request-file request.json --apply
codex_jobs.exe reload-queue --job-id <同じ子のジョブID>
```

要求には `job_id`、`owner_job_id`、`todo_id`、`parent_todo_id`、`kind`（research/check/review）、
`child_spec_sha256`、`parent_spec_sha256`、`prompt_sha256` を指定する。
ハッシュは保存済みの両仕様と子の原 `prompt.md` の正確なバイト列を指す。
操作者は原仕様を読み、独立した有限作業であることを確認して種類を指定する。
題名やPR番号だけから有限作業と推定しない。

プレビューも適用も既存のキュー、両ジョブの状態、共有ToDoの順にロックする。
子の監督プロセスは作成時刻まで照合し、子の実処理と親のプロセスは終了を確認する。
親の正常終了、親から子への結果待ち、両ToDoの原担当履歴、同一リポジトリとGit管理領域、
別々の専用worktreeと保存ブランチ、自動待機の原所有根拠が一致する場合に限る。
子から親への手動依存は間接的でも拒否する。

適用は原待機と根拠、要求、親の終了・待機状態を `work_wait_history` へ残す。
別の待機は保持する。状態が変わった再実行は再検証で拒否するため、応答が失われた場合は
同じジョブの履歴を確認してから次工程へ進む。

適用や監督の更新は実行開始を意味しない。元ジョブの開始時刻、元の作業場所、
実際のツール処理を確認する。レビュー完了・CI成功・製品完成もそれぞれ区別する。

## 書き込み担当が終了し、回収などの未完だけが残る場合

固定ソースを読む既存レビューを、書き込み担当のToDo全体の完了待ちにしない。
通常の手動依存は維持し、書き込み担当や回収のToDoを完了にしない。

```text
codex_jobs.exe reload-queue --job-id <元のレビューのジョブID>
codex_jobs.exe qualify-fixed-review --request-file request.json
codex_jobs.exe qualify-fixed-review --request-file request.json --apply
```

要求は `job_id/todo_id`、実際の主担当の `parent_job_id/parent_todo_id`、
元の自動待機が指す書き込み担当の `owner_job_id/owner_todo_id`、`read_only:true`、
両仕様と原promptの `child_spec_sha256/parent_spec_sha256/prompt_sha256`、
完全なcommit IDの `fixed_base/fixed_head` を持つ。他の項目は受け付けない。
主担当からレビューへの実際の結果待ちを確認する。書き込み担当からレビューへの依存を作らない。

元のジョブを複製せず、未開始・原履歴・専用作業場所・実リポジトリとGit管理領域、
両担当の正常終了とプロセス不在、現物に一致する一件の自動所有権待ちを照合する。
主担当の読取元が指定headで、追跡ファイルに変更がなく、baseがその祖先であることも確認する。
元の指示を読んだ操作者が、書き込みを行わない固定レビューとして明示的に指定する。
題名やPR番号だけで資格を推定しない。

古い起動側の権限指定を絞る場合は `launcher` 由来だけを対象にする。
明示された書き込み依頼を置き換えない。ネットワークは無効のまま保つ。
適用は原依頼と待機根拠・変更前の権限・照合時刻を履歴へ保存し、読み取り専用へ絞る。
共有ToDo、資源、モデル、原prompt、セッション、作業場所は変更しない。

先に標準の対象指定reloadで、元の監督プロセスを更新する。
新版が自身のPIDと作成時刻付きで対応を記録するまで資格の適用を拒否し、
古い監督が固定ソースの指示を追加せず実行を始める競合を防ぐ。
実行直前にも仕様と原promptのハッシュ、本人停止・依存・読み取り権限を再確認し、
元promptを保持したまま固定base/headと読み取り専用の指示を追加する。
別の稼働中の作者や通常の資源受付を免除する指定は保存しない。

固定レビューの実効起動方針は一か所で決める。保存済みの `mcp_profile` が
browser/fullでも、追加書き込み先、ホストChromeの橋渡し、プラグイン、アプリ、Web検索を
実行側では使わない。設定済みMCPサーバーを読み取り専用の一覧操作で列挙し、
各サーバーを個別に無効にする。一覧を取得できなければ起動しない。
後続の通常ブラウザ用引数で再び有効にしない。旧Chrome pipeの引数と環境変数も渡さない。
同じ固定レビューの要約・再開でもこの制限を保ち、通常のbrowser/full担当は変更しない。
対応確認の版は、この起動方針を実装した監督自身のPID・作成時刻とともに確認する。
